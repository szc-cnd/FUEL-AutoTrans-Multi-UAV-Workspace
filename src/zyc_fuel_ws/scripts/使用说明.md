## 项目概述

本目录下的脚本用于支撑一套基于无人机的自主探索与目标检测系统。系统由以下两个工作空间协同工作：

| 工作空间 | 路径（默认） | 用途 |
|---|---|---|
| `Fast-Drone-250` | `~/Fast-Drone-250` | 底层飞控、VINS 定位 |
| `zyc_fuel_ws` | `~/zyc_fuel_ws` | 探索规划、目标跟踪、可视化 |
| `shiyan_catkin_ws_target` | `~/shiyan_catkin_ws_target` | YOLO 目标检测、SORT 目标跟踪 |

```
scripts/

├── explore.sh                     # 完整启动：探索规划 + 目标检测 + 可视化

```

## Shell 脚本

### fast.sh — 快速启动基础模块

**功能：** 依次启动底层飞控驱动、VINS 定位到 MAVLink 桥接节点、位姿到里程计转换节点，并监听转换后的里程计数据。

**启动顺序：**

```
终端1（等待30秒）→  终端2（等待3秒）→  终端3（等待2秒）→  终端4
Fast-Drone-250 run.sh   vins_to_mavros_node   pose_to_odom_converter_node   rostopic echo /converted_odom
```

**用法：**

```bash
cd ~/zyc_fuel_ws/scripts     # 首次使用需赋权
sh fast.sh
```

**说明：**

- 脚本使用 `gnome-terminal` 自动打开多个终端窗口
- `sleep 30` 是等待 Fast-Drone-250 底层完全初始化的时间，若底层启动较慢可适当延长
- 最后一个终端会实时打印 `/converted_odom` 话题，用于确认里程计输出正常

> **注意：** `set -e` 已启用，若任何命令失败脚本将立即退出。请确保两个工作空间均已编译完成。

---

### explore.sh — 启动完整探索系统

**功能：** 在 `fast.sh` 基础之上，启动探索规划、YOLO 目标检测（含自动重启）、SORT 目标跟踪以及小球位置跟踪脚本。

**启动顺序：**

```
终端1（等待5秒）→  终端2（等待3秒）→  终端3（等待3秒）→  终端4
exploration.launch   yolo_ros.launch（失败自动重启）   sort_ros.launch   marker_wenzi_jisuan.py
```

**用法：**

```bash
# 请先运行 fast.sh，待底层正常后再运行 explore.sh
cd ~/zyc_fuel_ws/scripts
sh explore.sh
```

**说明：**

- YOLO 节点采用了 `until ... do ... done` 重试机制，启动失败会每隔 2 秒自动重启
- `marker_wenzi_jisuan.py` 负责订阅 `/ball_pose_tracking` 话题，自动聚合、过滤并在 RViz 中显示小球坐标标记，同时保存截图
- 脚本末尾有一段被注释掉的第五个终端（`fuel_nav`），如需手动导航可取消注释

> **提示：** 建议先手动验证每个节点单独启动无误，再使用本脚本一键启动。

---

### stop.sh — 停止所有进程

**功能：** 强制终止所有由 `fast.sh` 和 `explore.sh` 启动的进程，并清理所有 ROS 节点。

**用法：**

```bash
sh stop.sh
```

**覆盖的进程：**

| 进程关键字 | 对应模块 |
|---|---|
| `sh shfiles/rspx4.sh` | Fast-Drone-250 底层驱动 |
| `vins_to_mavros_node` | VINS 到 MAVLink 桥接 |
| `pose_to_odom_converter_node` | 位姿转换节点 |
| `roslaunch exploration_manager exploration.launch` | 探索规划 |
| `roslaunch yolo_detector yolo_ros.launch` | YOLO 目标检测 |
| `roslaunch sort_ros sort_ros.launch` | SORT 目标跟踪 |
| `python3 marker_wenzi_jisuan.py` | 小球位置跟踪 |
| `rosrun exploration_manager fuel_nav` | 手动导航节点 |

> **警告：** 脚本使用 `pkill -9` 强制终止进程，不会等待节点优雅退出。紧急情况使用，正常情况建议逐终端 `Ctrl+C`。

## Python 脚本

### marker_wenzi_jisuan.py — 小球位置跟踪器（主用版）

**功能：** 订阅目标检测输出的小球三维坐标话题，对多帧坐标进行统计过滤（剔除 2σ 外离群点）并计算均值，在 RViz 中发布球体与文字标记，同时缓存摄像头图像并在检测结束后自动保存截图。

**ROS 话题：**

| 方向 | 话题名 | 消息类型 | 说明 |
|---|---|---|---|
| 订阅 | `/ball_pose_tracking` | `geometry_msgs/PoseStamped` | 小球三维位置输入 |
| 订阅 | `/image_converter/output_video` | `sensor_msgs/Image` | 摄像头图像（用于截图） |
| 发布 | `visualization_marker` | `visualization_msgs/Marker` | RViz 可视化标记 |

**关键参数（代码内修改）：**

| 参数 | 默认值 | 说明 |
|---|---|---|
| `position_threshold` | 1.5 m | 判断是否为同一小球的位置差异阈值 |
| `image_buffer maxlen` | 100 帧 | 图像缓存最大帧数 |
| `screenshots_dir` | `~/explore_system/ball_screenshots/` | 截图保存目录 |
| 无新坐标判断超时 | 1.0 秒 | 超过此时间无新坐标则触发位置计算 |

**单独运行：**

```bash
cd ~/zyc_fuel_ws/scripts
source ~/zyc_fuel_ws/devel/setup.bash
python3 marker_wenzi_jisuan.py
```

**输出截图目录：** `~/explore_system/ball_screenshots/ball_<id>_<timestamp>.jpg`

---

### marker_wenzi_baoliu.py — 小球位置跟踪器（保留版）

**功能：** 功能与 `marker_wenzi_jisuan.py` 类似，但**不含图像缓存与截图**功能，代码更简洁。适合在无需截图或调试时使用。

**ROS 话题：**

| 方向 | 话题名 | 消息类型 |
|---|---|---|
| 订阅 | `/ball_pose_tracking` | `geometry_msgs/PoseStamped` |
| 发布 | `visualization_marker` | `visualization_msgs/Marker` |

> **注意：** 该版本**不进行重复小球过滤**，每次检测结束后均会将新位置追加到历史记录，可能导致同一小球被重复标记。

**单独运行：**

```bash
python3 marker_wenzi_baoliu.py
```

---

### marker_wenzi.py — 静态小球标记演示

**功能：** 手动在代码中硬编码小球坐标（x=3.22, y=-3.11, z=0.78），收到 `/detection_status` 为 `True` 的信号后延时 **3 秒**，在 RViz 中显示红色球体及坐标文字标记。

**ROS 话题：**

| 方向 | 话题名 | 消息类型 |
|---|---|---|
| 订阅 | `/detection_status` | `std_msgs/Bool` |
| 发布 | `visualization_marker` | `visualization_msgs/Marker` |

**适用场景：** 演示、调试 RViz 标记显示效果，或在已知目标坐标时做静态验证。

**单独运行：**

```bash
python3 marker_wenzi.py
```

> **注意：** 如需修改小球位置，请直接编辑脚本中第 41~43 行的 `pose.position.x/y/z`。

## 典型使用流程

```
步骤1: 启动底层与定位
  bash ~/zyc_fuel_ws/scripts/fast.sh
  （等待底层初始化完成，观察 /converted_odom 有数据输出）

步骤2: 启动探索与检测系统
  bash ~/zyc_fuel_ws/scripts/explore.sh

步骤3: 停止所有进程
  bash ~/zyc_fuel_ws/scripts/stop.sh
```
