## LDOP 动态目标轨迹预测设计

### 状态

本文档设计 LDOP 第三阶段中本轮要实现的基础预测能力：基于 tracker 稳定目标输出，按当前运动模型做基准轨迹外推，发布独立预测消息和 RViz 可视化。

本文档不替代第二阶段 tracker 设计。tracker 仍负责动态目标检测后的稳定 ID、类别、运动模型、模型原生状态和协方差维护；predictor 只消费 tracker 已经构造好的内部预测输入，不重新处理点云，不修改 tracker 当前消息语义，也不把未来预测回填到 `DynamicObject.msg`。

### 目标

- 新增独立 `DynamicObjectPredictor` 模块。
- 消费 `DynamicObjectTrackerFrameResult::prediction_inputs`。
- 对 tracker 稳定输出的全部动态目标做 1.0 秒短时预测。
- 每个目标输出一个预测分支，表示不额外假设意图、仅按当前运动模型做基准轨迹外推。
- 预测采样点保留模型原生状态和模型原生协方差，语义与 `DynamicObject.msg` 的 `model_state/model_covariance` 一致，只是表示未来采样时刻。
- 发布独立预测话题和独立预测 marker。
- 为后续航向/意图多分支预测、交互预测和规划风险层预留稳定接口。

### 非目标

- 不实现航向/意图多分支预测。
- 不实现目标间交互或目标-地图交互修正。
- 不实现闭环误差评估或概率反馈。
- 不新增目标数量限制。
- 不为低速或近似静止目标单独设置退化分支；预测输入已经是 tracker 确认的动态目标，速度大小只是当前状态的一部分。
- 不读取 tracker filter 内部自适应 `Q/R` 状态。

### 命名

本轮能力称为“轨迹外推”，不称为“线性外推”。原因是 predictor 按 `motion_model_type` 传播模型原生状态：`CV3D/CA2D/CA3D` 可能表现为直线、近似线性或加速度轨迹，`CTRA` 会保留速度、加速度、航向和角速度，因此可以产生转弯曲线。统一称为轨迹外推更准确。

### 架构

主流程增加 predictor，顺序为：

```text
UFOMap 动静态分割
  -> DynamicObjectClusterer 当前帧检测
  -> DynamicObjectTracker 稳定目标跟踪
  -> DynamicObjectPredictor 轨迹外推预测
  -> Ldop::publishFrame() 统一发布
```

`DynamicObjectPredictor` 构造时读取预测相关 ROS 参数，提供单一主流程入口：

```cpp
DynamicObjectPredictorFrameResult predict(
    const std_msgs::Header& header,
    const std::vector<TrackPredictionInput>& inputs);
```

返回结构与现有 clusterer/tracker 风格一致：

```cpp
struct DynamicObjectPredictorTimingStats {
  double predict_dynamic_objects_ms{0.0};
  double build_prediction_markers_ms{0.0};
};

struct DynamicObjectPredictorFrameResult {
  ldop::DynamicObjectPredictionArray predictions_msg;
  visualization_msgs::MarkerArray prediction_markers_msg;
  DynamicObjectPredictorTimingStats timing;
};
```

`Ldop::processFrame()` 在 tracker 后调用 predictor，把预测消息和 marker 放进 `ProcessedFrame`；`Ldop::publishFrame()` 统一发布。

### 消息

新增 4 个消息：

```text
DynamicObjectPredictionArray.msg
DynamicObjectPrediction.msg
DynamicObjectPredictionBranch.msg
DynamicObjectPredictionPoint.msg
```

数组消息：

```text
std_msgs/Header header
DynamicObjectPrediction[] predictions
```

单目标预测消息：

```text
uint8 CLASS_UNKNOWN=0
uint8 CLASS_HUMAN=1
uint8 CLASS_VEHICLE=2
uint8 CLASS_UAV=3
uint8 CLASS_OTHER=4

uint8 MOTION_MODEL_CA2D=0
uint8 MOTION_MODEL_CA3D=1
uint8 MOTION_MODEL_CV3D=2
uint8 MOTION_MODEL_CTRA=3

uint32 id
geometry_msgs/Vector3 size
uint8 object_class
uint8 motion_model_type
bool matched_in_current_frame
DynamicObjectPredictionBranch[] branches
```

`motion_model_type` 是解释所有采样点 `model_state/model_covariance` 布局的键。第一版同一个目标的所有预测分支都使用同一个运动模型类型。

类别和运动模型常量与 `DynamicObject.msg` 保持一致，避免预测消息消费者维护第二套数字映射。

预测分支消息：

```text
uint8 BEHAVIOR_BASELINE=0
uint8 BEHAVIOR_LONGITUDINAL=1
uint8 BEHAVIOR_VERTICAL=2
uint8 BEHAVIOR_TURNING=3
uint8 BEHAVIOR_LATERAL=4

uint8 behavior_type
float64 behavior_value
float64 probability
DynamicObjectPredictionPoint[] points
```

`BEHAVIOR_BASELINE` 只用于本轮基准轨迹外推，表示不额外假设意图。后续多意图或交互预测不再使用该行为类型，而是使用纵向、垂向、转向或横向等明确行为族。

`behavior_value` 是 `[-1.0, 1.0]` 的归一化有符号行为强度，不承载真实物理单位。第一版固定为 `0.0`。

预测采样点消息：

```text
duration time_from_start
float64[] model_state
float64[] model_covariance
float64 influence_weight
```

`model_state` 和 `model_covariance` 的语义与 `DynamicObject.msg` 完全一致，只是表示未来采样时刻的预测状态。`model_covariance` 仍按 row-major 展开，长度为 `len(model_state)^2`。

### 参数

新增参数：

```yaml
prediction_horizon: 1.0
dynamic_predictions_topic: /ldop/dynamic_object_predictions
dynamic_prediction_markers_topic: /ldop/dynamic_prediction_markers
```

复用参数：

```yaml
tracking_default_dt: 0.1
```

predictor 自己读取 `tracking_default_dt` 作为预测采样间隔。这里是参数名复用，不通过 `Ldop` 把 tracker 的内部参数值注入 predictor，从而保持模块边界稳定。

不新增这些参数：

```text
prediction_dt
prediction_max_objects
prediction_min_speed
prediction_influence_full_time
prediction_min_influence_weight
```

尾部最小影响权重固定为 `0.3`。

### 轨迹外推

predictor 对每个 `TrackPredictionInput` 生成一个预测分支：

```text
behavior_type = BEHAVIOR_BASELINE
behavior_value = 0.0
probability = 1.0
```

按 `motion_model_type` 创建对应 `MotionModel`：

- `CA2D`：水平面 constant acceleration，z 保持。
- `CA3D`：三维 constant acceleration。
- `CV3D`：三维 constant velocity。
- `CTRA`：带速度、加速度、航向和角速度的转弯模型。

从 tracker 输入开始：

```text
state0 = TrackPredictionInput.model_state
P0 = TrackPredictionInput.model_covariance
```

每一步：

```text
F = motion_model.getTransitionF(state_before)
state_next = motion_model.stateTransition(state_before)
Q = motion_model.getProcessNoiseQ()
P_next = F * P * F^T + Q
```

`P0` 来自 tracker 当前输出的 `model_covariance`，已经包含 tracker 当前滤波和自适应噪声估计后的结果。未来传播新增过程噪声使用运动模型基础 `Q`，即 `MotionModel::getProcessNoiseQ()`；第一版不读取 tracker filter 内部自适应 `process_noise_`，也不扩大 `TrackPredictionInput` 去导出 filter 内部噪声状态。

CTRA 的协方差传播使用预测前状态处的雅可比 `F`，与当前 EKF predict 语义一致。

### 影响权重

`model_covariance` 保持模型真实传播，不为了规划影响做人为缩小。规划和 RViz 影响用 `influence_weight` 表达：

```text
if time_from_start <= prediction_horizon * 0.5:
  influence_weight = 1.0
else:
  influence_weight 从 1.0 线性衰减到 0.3
```

`0.3` 写死，不新增参数。这样远端预测仍保留风险提示，但不会因为远端协方差增大而把规划可通行区域过度压缩。

### 可视化

预测 marker 话题为 `/ldop/dynamic_prediction_markers`，可通过 `dynamic_prediction_markers_topic` 配置。

MarkerArray 首个 marker 使用 `DELETEALL`，延续当前动态目标 marker 和轨迹 marker 风格。

每个目标输出：

- 一条预测轨迹线：`LINE_STRIP`，连接每个采样点的中心位置 `model_state[0..2]`。
- 多个不确定性椭球：每个采样点一个 `SPHERE` marker。

椭球来自 `model_covariance` 的前三维位置协方差子块。对 3x3 位置协方差做特征分解，使用主轴方向作为 marker 姿态，使用 1σ 作为椭球尺度：

```text
scale_i = 2 * sqrt(lambda_i)
```

RViz `SPHERE.scale` 表示直径，因此乘以 2。若数值误差产生极小负特征值，裁剪到 0。

marker alpha 乘以采样点 `influence_weight`。漏检延续但尚未删除的稳定轨迹继续预测，但 marker 整体透明度降低，以表达当前帧未匹配。

### 内部契约

`TrackPredictionInput` 来自 tracker 内部稳定输出，不作为外部不可信输入。predictor 不对状态维度、协方差方阵性和有限性做外部输入式重复兜底；实现中用 assert 或清晰的状态维度契约表达不变量。

predictor 不额外裁剪目标数量。是否稳定发布、是否进入预测输入，由 tracker 的 `min_hits_to_publish` 等规则控制。

## LDOP 动态目标航向/意图 GMM 多轨迹预测设计

### 状态

本文档细化 LDOP 第三阶段 P2：在已实现的基础轨迹外推之上，加入航向/意图多分支预测，输出 branch-level trajectory-level GMM，并在 RViz 中显示每条分支的中心状态轨迹。

当前代码已经按本文档的 P2 主线落地：`DynamicObjectPredictor` 直接生成多条航向/意图预测分支，旧 `BEHAVIOR_BASELINE` 枚举已移除，RViz 只显示真实保留的 GMM 分支中心状态线，不再显示协方差椭球或额外采样轨迹。

2026-05-21 状态补充：本文档仍只描述 P2 的设计边界；后续 P3 交互感知预测和 P4 predictor 内部在线闭环反馈已经另文实现，LDOP 第三阶段轨迹预测内容已完成。

本设计基于以下既有边界：

- P1 已实现 `DynamicObjectPredictor`，并在 tracker 后接入 LDOP 主流程。
- tracker 已提供 `TrackPredictionInput`，包含稳定 ID、类别、运动模型、模型原生状态、模型原生协方差、bbox、历史轨迹和生命周期信息。
- 预测消息已经支持 `DynamicObjectPredictionBranch[]`，每条 branch 有 `behavior_type`、`behavior_value`、`probability` 和未来 `points[]`。
- P2 不重新处理点云，不修改 tracker 当前输出语义，不把未来预测写回 `DynamicObject.msg`。

### 目标

- 在 `DynamicObjectPredictor` 内部生成多条航向/意图候选分支。
- 每条分支独立 rollout 未来模型原生状态和模型原生协方差。
- 每个目标输出概率归一化的 branch-level trajectory-level GMM。
- 基于历史运动特征、类别、运动模型、历史长度和漏检状态分配 P2 初始概率。
- P2 是当前 predictor 的唯一轨迹预测路径；不再保留旧单分支回退开关。
- 在 RViz 中显示多分支中心状态轨迹。
- 不引入额外 sampled trajectories，保持 `/ldop/dynamic_object_predictions` 和可视化表达一致。

### 非目标

- 不实现目标间交互能量。
- 不实现目标与地图交互能量。
- 不实现 NIS 或预测残差闭环概率反馈。
- 不新增采样轨迹 ROS 消息字段、独立 samples 话题或 sample marker。
- 不导出 tracker 内部自适应 `process_noise_`。
- 不修改 `DynamicObject.msg`。

### 架构

P2 仍只增强 `DynamicObjectPredictor`，外部调用关系不变：

```text
DynamicObjectTracker
  -> TrackPredictionInput[]
  -> DynamicObjectPredictor::predict()
  -> /ldop/dynamic_object_predictions
  -> /ldop/dynamic_prediction_markers
```

predictor 内部数据流为：

```text
TrackPredictionInput
  -> MotionHistoryFeatures
  -> PredictionMode[]
  -> DynamicObjectPredictionBranch[]
```

`predict()` 仍是唯一主入口。P2 复杂度通过私有 helper 组织，避免向 tracker、LDOP 主流程或 ROS 消息层泄漏实现细节。

### 内部结构

`MotionHistoryFeatures` 是 predictor 内部的历史运动摘要，来自 `input.history` 和当前 `model_state`。它表达：

- 稳定航向。
- 当前速度和历史速度趋势。
- 加速度趋势。
- yaw 或曲率趋势。
- z 方向速度或高度变化趋势。
- 历史长度质量。
- 漏检延续惩罚。
- 航向或速度不稳定程度。

`PredictionMode` 是 predictor 内部的候选意图描述，转换为 ROS branch 前使用：

```text
behavior_type
behavior_value
probability
history_quality_scale
mode_uncertainty_scale
rollout_modifier
```

`rollout_modifier` 只在 predictor 内部使用，用于决定该 mode 如何改写未来候选走法。它不作为公共接口发布。

一个 `PredictionMode` 最终对应一个 GMM component，也就是一个 `DynamicObjectPredictionBranch`。当前 P2 中每个分支内部只有一条 rollout 得到的中心状态序列 `points[]`，以及每个时间点对应的 `model_covariance`；分支内部没有多条原始预测轨迹样本。`prediction_max_branches` 和 `prediction_min_branch_probability` 都作用在这些 GMM component 上，而不是作用在分支内部的时间采样点或额外轨迹样本上。

### Mode 候选集合

P2 使用完整但受控的候选集合：

```text
keep / trend-follow
longitudinal-decelerate
longitudinal-stop
turn-left
turn-right
lateral-left
lateral-right
vertical-climb
vertical-descend
vertical-hold
```

映射到现有消息时不新增枚举：

```text
keep / trend-follow          -> BEHAVIOR_LONGITUDINAL, value = 0.0 或正小值
decelerate / stop            -> BEHAVIOR_LONGITUDINAL, value < 0
turn-left / turn-right       -> BEHAVIOR_TURNING, value = +/- strength
lateral-left / lateral-right -> BEHAVIOR_LATERAL, value = +/- strength
climb / descend / hold-z     -> BEHAVIOR_VERTICAL, value = + / - / 0
```

旧单分支行为枚举已从预测分支消息中删除。P2 正常输出不提供单分支回退路径，也不提供 `prediction_enable_intent_gmm=false` 开关。

### 类别策略

候选 mode 按类别和运动模型选择：

- human：生成 `keep`、`longitudinal-decelerate`、`longitudinal-stop`、`lateral-left/right`、`turn-left/right`。人类目标允许更灵活的横向偏转和停止假设。
- vehicle：生成 `keep`、`longitudinal-decelerate`、`turn-left/right`。车辆默认不生成 lateral 分支，除非后续设计有明确道路或交互证据。
- UAV：生成 `keep`、`longitudinal-decelerate`、`turn-left/right`、`vertical-climb/descend/hold`。UAV 可以表达 2.5D 意图。
- other / unknown：以 `keep` 为主，只在历史航向不稳定、速度趋势明显或 z 方向证据明显时生成低权重候选。

分支数量受 `prediction_max_branches` 控制。候选 mode 先通过 softmax 得到分支概率，再删除低于 `prediction_min_branch_probability` 的 GMM component；如果剩余分支数仍超过 `prediction_max_branches`，按概率从高到低保留前 N 个，最后对保留分支重新归一化。

### 概率策略

P2 概率先使用启发式 logit 归一化，不做 P4 闭环递推：

```text
score_z = class_prior_z
        + history_heading_score_z
        + speed_trend_score_z
        + yaw_or_curvature_score_z
        + vertical_trend_score_z
        - short_history_penalty_z
        - missed_frame_penalty_z

probability_z = softmax(score_z)
```

含义如下：

- 历史航向越稳定，`keep/trend-follow` 概率越高。
- 速度持续下降时，`longitudinal-decelerate` 和 `longitudinal-stop` 增权。
- yaw、曲率或水平航向变化明显时，`turn-left/right` 增权。
- z 速度或高度趋势明显时，UAV 的 `vertical-climb/descend` 增权。
- 短历史和漏检延续降低尖锐判断，使分布更平缓。
- 低于 `prediction_min_branch_probability` 的 GMM 分支可丢弃；若剩余数量超过 `prediction_max_branches`，只保留概率最高的前 N 个。最终发布前重新归一化概率和为 1。

概率总和必须为 1。若所有候选被阈值过滤，保留概率最高分支并设置为 1。

### Rollout 机制

每个 mode 从同一个当前输入拷贝开始：

```text
state0 = input.model_state
P0 = input.model_covariance
```

mode 只改变未来候选走法，不修改 tracker 当前状态，也不影响其他分支。

状态布局按当前运动模型解释：

```text
CV3D: [x,y,z,vx,vy,vz]
CA2D: [x,y,z,vx,vy,ax,ay]
CA3D: [x,y,z,vx,vy,vz,ax,ay,az]
CTRA: [x,y,z,v,a,yaw,yaw_rate]
```

mode 对状态的影响保持局部和可解释：

- `keep/trend-follow`：保持现有运动模型传播。
- `longitudinal-decelerate`：沿稳定航向降低速度或加速度。
- `longitudinal-stop`：让速度在预测 horizon 内逐步趋近停止，不因当前速度小而切换算法。
- `turn-left/right`：对 CTRA 调整 `yaw_rate`；对 CV/CA 用旋转后的水平速度或加速度近似。
- `lateral-left/right`：在稳定航向法向加入小横向速度分量，主要用于 human。
- `vertical-climb/descend/hold`：调整 z 方向速度或加速度，仅用于 UAV 或 z 方向证据明显目标。

每一步仍使用现有运动模型传播：

```text
F = motion_model.getTransitionF(state_before)
state_next = modified_state_transition(state_before, mode)
P_next = F * P * F^T + Q_future
```

`modified_state_transition()` 表示在当前 mode 下对候选状态的有限改写。实现时应尽量靠近现有 `MotionModel` 传播流程，偏离基础模型的地方用中文注释说明原因。

### 未来过程噪声

P2 不导出 tracker 内部自适应 `process_noise_`。当前滤波和自适应噪声的历史影响通过 `input.model_covariance` 作为 `P0` 进入预测。

未来 rollout 使用：

```text
Q_future = Q_base * history_quality_scale * mode_uncertainty_scale
P_next = F * P * F^T + Q_future
```

`Q_base` 来自 `MotionModel::getProcessNoiseQ()`。`history_quality_scale` 表达轨迹输入质量，短历史、漏检延续、航向或速度不稳定时增大。`mode_uncertainty_scale` 表达候选假设强度，`keep` 接近 1，`decelerate/stop` 稍大，`turn/lateral/vertical` 更大但有上限。

这一区分保证：

- `P0` 表示 tracker 当前状态估计不确定性。
- `Q_future` 表示未来候选意图假设的不确定性。
- P2 不与 tracker filter 内部实现强耦合。
- 后续 P4 已用 NIS / residual / likelihood 闭环校准下一帧同语义分支概率和 predictor 未来过程噪声尺度；这不改变本文档中的 P2 概率初始化语义。

### 参数

新增 predictor 参数集中写入 `DynamicObjectPredictorParams` 默认值，并由 `loadParameters()` 使用三参数 `pnh_.param(name, target, default_value)` 读取。

当前 YAML 运行参数：

```yaml
prediction_max_branches: 3
prediction_min_branch_probability: 0.05

prediction_history_window: 20
prediction_heading_stable_angle: 0.35
prediction_stop_speed: 0.2

prediction_turn_yaw_rate: 0.5
prediction_lateral_speed: 0.4
prediction_vertical_speed: 0.3

prediction_history_quality_noise_scale: 1.5
prediction_hypothesis_noise_scale: 1.3
```

参数语义：

- `prediction_max_branches` 控制每个目标最多输出多少 GMM component，不控制单个分支内部的时间采样点数量。
- `prediction_min_branch_probability` 控制低概率 GMM component 过滤，不作用于分支内的 `points[]`。
- `prediction_history_window` 控制用于航向和趋势估计的历史样本数量。
- `prediction_heading_stable_angle` 控制航向稳定性判断。
- `prediction_stop_speed` 用于判断停止倾向和 stop rollout 目标速度。
- `prediction_turn_yaw_rate`、`prediction_lateral_speed`、`prediction_vertical_speed` 控制候选分支的物理强度。
- `prediction_history_quality_noise_scale` 和 `prediction_hypothesis_noise_scale` 控制 P2 有限噪声放大，不做无界膨胀。

`DynamicObjectPredictorParams` 仍保留模块内兜底默认值；当前 `config/ldop.yaml` 显式给出运行默认值。`buildPredictorConfig()` 只做参数到运行时配置的语义转换和简单范围兜底。

### RViz 可视化

P2 marker 只输出一类：

- branch center-state line：每条分支一条中心状态轨迹线，连接该分支各未来时间点 `model_state[0..2]`，透明度按 branch probability 调整。

采样轨迹不进入 `/ldop/dynamic_object_predictions`，也不在 RViz 中额外绘制。此前仅用于可视化的 sample markers 已删除，因为它不服务实际规划或评估契约；规划器和评估器应优先直接消费 GMM branches，只有算法内部明确需要 Monte Carlo samples 时才在消费端临时派生。

### 边界情况

- 短历史：仍输出多分支，但降低尖锐概率判断，使概率更平缓。
- 漏检延续：继续预测，整体可视化透明度降低，并提高 `history_quality_scale`。
- 低速目标：不切换到独立算法；是否停止由历史速度趋势和 stop mode 概率表达。
- 类别 unknown：以保守 `keep` 为主，低权重补充分支只在运动证据明显时生成。
- 概率裁剪后空集合：保留裁剪前最高分支，概率设为 1。
- 不生成 sample markers，避免 RViz 出现不服务实际输出契约的额外轨迹线。

### 验收标准

- 每个稳定目标可输出多条航向/意图分支。
- 每条分支有独立未来状态、协方差、行为族、行为强度和概率。
- 概率总和归一化。
- MAP 分支通常与历史趋势一致。
- RViz 能检查多分支中心状态轨迹。
- P2 不保留旧单分支回退；消融实验通过分支数量和概率阈值控制。
- 不改变 `DynamicObject.msg`，不新增 samples 消息字段，不引入 P3/P4 责任。

## LDOP 动态目标交互感知 GMM 多轨迹预测设计

### 状态

本文档细化 LDOP 第三阶段里的轨迹预测内部 P3：在已经完成的轨迹外推与航向/意图 GMM 多分支预测之上，引入目标间交互和目标-地图交互，使预测分支概率和必要的中心轨迹均值能反映动态目标之间的冲突、静态障碍约束和局部可通行方向。

当前已确认边界：

- P1 轨迹外推已完成。
- P2 航向/意图 GMM 已完成，predictor 当前输出 branch-level trajectory-level GMM。
- P3 交互感知预测已完成；后续 P4 predictor 内部在线闭环反馈也已另文实现，因此 LDOP 第三阶段轨迹预测内容已经完成。
- UFOMap 应用层借鉴点 1、3、4 已作为 P3/P4 跨阶段基础落地：显式 `Unknown/Free/Occupied/OutOfMap` 状态、可配置 query depth 和最近 occupied 查询。
- RViz 预测 marker 当前只显示真实保留 GMM 分支中心状态线，不恢复额外 sample marker。
- P3 不修改 `DynamicObject.msg`，不把未来预测回填到 tracker 当前状态消息。

### 目标

- 同时引入目标间交互和静态地图约束。
- 使用 UFOMap 占据/近障碍软代价和局部 free corridor 方向先验。
- 以分支概率重权重为主，对明显穿障、过近或迎面冲突的分支允许轻量中心轨迹修正。
- 新建独立 `PredictionInteractionContext` 模块聚合交互/地图证据，避免 `DynamicObjectPredictor` 直接承担地图查询和场景理解职责。
- 保持 `/ldop/dynamic_object_predictions` 的 planner-facing GMM 输出结构不变。
- 为第四阶段类 ROG-Map 风险/局部地图构建保留清晰边界。
- 让 P3 地图交互使用已经落地的基础 UFOMap 查询能力，但不把静态膨胀、批量 service、线段检查或 ESDF/local map 提前混入 predictor。

### 非目标

- 不在本文档的 P3 范围内实现闭环预测误差缓存、NIS 校准或概率反馈；这些已由后续 P4 predictor 内部在线反馈另文实现。
- 不实现第四阶段 planner-facing 类 ROG-Map 或风险地图构建器。
- 不实现 UFOMap 应用层借鉴点 2、5、6：`BoundingVolume-lite` 几何查询抽象、swept-volume 辅助线段检查、完整/局部地图发布后置增强。
- 不新增预测 sample 消息字段、sample marker 或默认诊断 marker。
- 不引入学习式 interaction encoder。
- 不把每个能量项公式细节全部暴露为 YAML 参数。

### 架构边界

P3 增加独立 `PredictionInteractionContext`，位置在 P2 candidate branches 与 predictor 分支重权重之间：

```text
UFOMap / static map query
TrackPredictionInput[]
P2 candidate branches
  -> PredictionInteractionContext
       - pair interaction cost
       - map / near-obstacle cost
       - free corridor prior
       - lightweight correction suggestion
       - internal diagnostics
  -> DynamicObjectPredictor applies:
       - probability reweighting
       - smooth control profile and model rollout
  -> /ldop/dynamic_object_predictions
  -> /ldop/dynamic_prediction_markers
```

`PredictionInteractionContext` 是预测阶段的交互/地图约束上下文，不是第四阶段 planner-facing 类 ROG-Map 地图。第四阶段应单独实现风险/局部地图 builder，但该 builder 可以复用 `PredictionInteractionContext` 输出的局部交互证据、地图约束证据、显式 occupancy state、query-depth 策略、最近 occupied 证据和风险摘要，避免重复实现目标间关系、近障碍查询和 free corridor 估计。

边界应保持为：

```text
PredictionInteractionContext:
  负责从 tracker/prediction/UFOMap 查询中提取局部约束证据和分支风险摘要

DynamicObjectPredictor:
  负责把约束证据应用到 GMM 分支概率，并把局部修正 hint 转成时间平滑控制后重新 rollout 中心轨迹

P4 risk / local map builder:
  负责把预测分支、概率、协方差、目标尺寸和局部约束证据转成 planner-facing 类 ROG-Map / 动态风险地图
```

因此 P4 可以使用这个新增模块，但不应把它当成最终规划地图。它是 P3 与 P4 共享的场景证据层，输出应保持稳定、结构化，避免只作为 predictor 私有 helper 存在。

### 交互能量

P3 总能量由三类代价组成：

```text
total_energy =
  w_pair * pair_cost
+ w_map * map_cost
+ w_corridor * corridor_cost
```

#### 目标间代价

目标间交互首版使用可解释几何项：

```text
pair_cost =
  close_distance_penalty
+ ttc_penalty
+ opposing_or_crossing_penalty
```

- `close_distance_penalty`：未来采样点距离低于目标尺寸膨胀后的 `prediction_interaction_safe_distance` 时增大。
- `ttc_penalty`：相对速度指向接近，且预计在 `prediction_ttc_safe_time` 内过近时增大。
- `opposing_or_crossing_penalty`：用相对速度夹角区分迎面、交叉和追随；迎面和交叉高于同向追随。

首版不做复杂博弈优先级，只对明显冲突分支降权，并给出小幅减速或侧向避让建议。

#### 地图代价

地图约束包含占据/近障碍软代价和 free corridor 方向先验：

```text
map_cost =
  occupied_penalty
+ near_obstacle_penalty

corridor_cost =
  heading_to_free_corridor_penalty
```

- `occupied_penalty`：预测点或目标尺寸膨胀半径进入 UFOMap occupied 区域时增大。
- `near_obstacle_penalty`：预测点接近 occupied 区域但未穿障时给出软惩罚。
- `heading_to_free_corridor_penalty`：局部可通行方向明确时，分支航向越背离该方向，代价越高。

free corridor 方向由局部采样估计；如果方向不明确，不生成方向修正，只保留 occupied/near-obstacle 软代价。

### 概率重权重与轻量修正

每个目标内对每个 branch 应用：

```text
branch.probability *= exp(-total_energy / tau)
```

随后对该目标的保留分支重新归一化。若所有分支都被强烈惩罚，仍保留概率最高分支，避免输出空预测。

轻量轨迹修正只作用于明显高风险分支，并受参数上限约束：

- 穿障或近障碍：生成沿推离障碍方向的受限位置偏置 hint。
- 迎面或过近：生成受限减速或侧向避让 hint。
- free corridor 明确：生成朝可通行方向的小幅方向偏置 hint。

这些 hint 不直接逐点改写预测位置，而是在 predictor 内被平滑成随时间连续的控制 profile，再交给运动模型重新 rollout。协方差不因为交互代价被人为缩小。若后续认为修正代表更强假设，可以小幅放大对应分支未来过程不确定性；P3 首版先修正概率，并通过平滑控制重新生成均值轨迹。

### 数据流

P3 保持两段式流程，避免交互逻辑侵入 P2 mode 生成：

```text
1. DynamicObjectPredictor 按 P2 生成 candidate branches
2. PredictionInteractionContext 对这些 branches 做交互/地图评估
3. DynamicObjectPredictor 应用 context result：
   - branch.probability *= probability_scale
   - convert point correction hints to smooth control profile
   - rerollout branch points with the original motion model
   - renormalize branches per object
4. buildPredictionMarkers() 仍只画保留后的真实 GMM 分支线
```


### 地图查询与预算策略

#### 职责边界

P3 使用现有 `UfomapMapper` 的只读查询能力，但 predictor 和 `PredictionInteractionContext` 都不直接访问 UFOMap runtime。`PredictionInteractionContext` 定义抽象查询语义，例如“点是否占据”“邻域是否靠近障碍”“局部可通行方向是什么”；运行时由持有 `UfomapMapper` 实例的 `Ldop` 或上层对象把这些语义适配到具体 UFOMap 查询函数。

不让 `PredictionInteractionContext` 自己构造 concrete UFOMap adapter，原因是：

- `UfomapMapper` 的生命周期和线程锁由 `Ldop` 当前主流程管理，context 不应反向拥有或复制地图模块。
- 第四阶段 risk/local map builder 也要复用同一套场景证据接口；把 adapter 注入而不是内建在 context 里，更容易让 P3/P4 共用。
- 地图不可用时，上层可以传入空 adapter 或 unavailable 状态，context 明确退化为 `map_cost = 0`。

#### 查询接口选择

具体 UFOMap 查询应按场景分层：

| 场景 | 建议查询 | 用途 |
|------|----------|------|
| 预测采样点或目标膨胀中心是否落在 occupied / free / unknown / out-of-map 体素 | `UfomapMapper::queryNode(point)` | 保留为抽象点查询能力；当前已返回显式 occupancy state，性能优化后的 P3 主路径不逐点调用它 |
| 预测点是否位于已知 free 区域 | `UfomapMapper::seenFree(point)` 和 `queryNode()` 中的 `Free` 状态 | 区分 free 与 unknown/occupied，用于 free corridor 采样和未知空间保守处理；`seenFree()` 仍是动静态判别证据，不等同于 P4 planner-facing `FREE` |
| 预测点膨胀半径内是否有静态 occupied/near obstacle 节点 | `UfomapMapper::queryLocalOccupied(query)`，内部使用 UFOMap 空间谓词 `Intersects(Sphere(center, radius))`、`Leaf(depth)`、`HitsMin(1)` | 做静态近障碍软代价、最近障碍距离近似和 occupied overlap 估计；`prediction_map_query_depth` 可调节 coarse/fine 查询 |
| 局部最近静态 occupied 证据 | `UfomapMapper::queryNearestOccupied(center, radius, max_results, query_depth)` | 为 P3 地图代价和 P4 后续距离接口提供 bounded nearest-obstacle 近似；不承诺 ESDF 的连续 signed distance 或 gradient |
| 局部 free corridor 方向估计 | 每个分支代表点周围 8 个水平 `seenFree()` 探针 | 比较候选方向上的 free 证据，得到 `free_corridor_direction` 和置信度；不使用 `points * directions` 查询 |

P3 不使用 `setNodeLabel()`、`clearAllLabels()` 等写接口，也不把 `queryDynamicCandidates()` 作为静态近障碍查询主接口。`queryDynamicCandidates()` 当前带有 dynamic candidate / label / seenFree 语义，更适合当前动静态分割或动态候选点流程；P3 的地图代价需要查询静态占据或近障碍区域，应新增命名中性的只读区域查询封装。该封装可以直接在 `UfomapMapper` 内部使用 UFOMap 的区域查询能力，例如 `map.query(Leaf && HitsMin && Intersects(...))`，必要时后续再补最近邻查询或批量查询接口。

#### 静态/动态来源分离

静态地图约束和动态目标交互的来源必须分离：

- 静态障碍、近障碍和 free corridor 来自 `UfomapMapper` 管理的 UFOMap 静态/占据查询。
- 动态目标之间的距离、TTC、occupied overlap 和风险来自 tracker 传入的 `TrackPredictionInput[]`、目标 `size` 以及 predictor 已生成的未来 GMM 分支。
- 不从 UFOMap 的动态体素或动态候选查询中反推未来动态目标风险；这类信息会比 tracker 的稳定 ID、模型状态、尺寸和预测分支更粗糙，也容易把当前帧动态点云语义和未来预测语义混在一起。

#### 分支级查询预算

P3 不缓存一整份 UFOMap 地图：

- UFOMap 已由 `UfomapMapper` 维护，并用读写锁保护。
- 完整复制地图会增加内存和同步成本，并可能让预测使用过期地图。
- P3 只需要未来分支附近的局部占据、近障碍和可通行方向信息。

当前实现采用分支级查询预算，而不是 `LocalOccupiedCacheKey` / `unordered_map` 形式的单帧局部缓存：

- map cost 每个预测分支只做一次 `queryLocalOccupied()`：构造覆盖短时 rollout、目标外接圆和近障碍半径的局部查询球，再在内存中对各采样点计算 signed distance、occupied overlap 和 near-obstacle 代价。
- P3 主路径需要最近 occupied 证据时，优先在同一次 `queryLocalOccupied()` 返回的局部列表里内存计算最近障碍，避免额外查询；`queryNearestOccupied()` 作为直接查询接口保留下来，供 P4 planner-facing 距离摘要或调试路径复用。
- free corridor 每个预测分支只做 8 个水平 `seenFree()` 探针：使用分支时间中点作为代表点，避免查询次数随 `points * directions` 放大。
- 这个预算比缓存更稳定：它直接限制地图查询上限，不依赖不同分支是否刚好命中相同离散 key。若后续 LDOP 第四阶段风险地图或 3D UAV 场景需要 26 邻域，应作为可配置增强，并重新评估 `applyInteractionContext` 耗时。

#### 性能扩展

若后续性能瓶颈来自反复获取 UFOMap 读锁，可以在 `UfomapMapper` 侧补充批量只读查询接口，让 adapter 在一次读锁内完成一组局部查询；这仍不是复制地图，而是优化查询路径。

### 边界情况

- 没有地图或地图查询失败：`map_cost = 0`，只使用目标间交互；诊断记录 `map_unavailable`。
- 单目标：`pair_cost = 0`，只使用地图约束。
- 所有分支都被强烈惩罚：保留概率最高分支并重新归一化。
- free corridor 不明确：不做方向修正，只保留 occupied/near-obstacle 软惩罚。
- 漏检延续目标：不特殊删除，交互/地图代价继续作用，RViz 透明度沿用现有 coasting 逻辑。
- 地图修正和目标间修正方向冲突：优先避免穿障和近障碍；目标间侧向避让作为次级建议。

`TrackPredictionInput` 和 prediction branches 仍按内部契约处理，用 assert 表达状态维度等不变量。地图查询属于跨模块边界，必须显式处理可用性，不能让查询失败中断 predictor 输出。

## LDOP 动态目标闭环概率反馈 P4 设计

### 状态

本文档细化 LDOP 第三阶段里的轨迹预测内部 P4：在已经完成的 P1 轨迹外推、P2 航向/意图 GMM 多分支预测和 P3 交互感知重权重/轻量修正之上，引入预测残差、NIS 和 likelihood 闭环反馈，使同一目标的下一帧预测概率和未来过程噪声尺度能根据上一轮预测是否解释当前观测而调整。

2026-05-21 状态补充：本文档对应的 P4 predictor 内部在线反馈已经实现并通过本地验证；因此 LDOP 第三阶段动态目标短时轨迹预测内容已经完成。离线多 horizon evaluator 和 LDOP 第四阶段 planner-facing 风险地图仍作为后续工作独立推进。

当前已确认边界：

- P4 默认启用在线反馈，并提供参数关闭。
- 反馈状态按 `object_id` 维护，只影响同一目标的短期预测，不做类别级或全局泛化。
- 反馈同时调整分支概率和过程噪声尺度。
- 分支概率可以增大或降低；过程噪声尺度允许在 `[min, max]` 内变化，默认下界为 0.3，避免预测 Q 被压到 0。
- P4 不修改 tracker 当前状态，不改变 `DynamicObject.msg`，不新增默认 ROS 诊断消息。

### 目标

- 在 `DynamicObjectPredictor` 内部维护上一轮预测缓存和短期反馈状态。
- 使用当前 tracker 输出按目标 ID 对齐上一轮预测，计算每个预测分支的 residual、NIS 和 Gaussian likelihood。
- 将上一轮分支解释当前观测的能力反馈到下一轮同语义 mode 的 score bias。
- 当某个 mode 长期 NIS 偏大时，放大该 mode 的未来过程噪声尺度，避免分支过度自信。
- 当 NIS 偏低或长期稳定时，过程噪声尺度可缓慢降低到固定下界 0.3，用于校准 predictor 自定义的未来 Q。
- 保持 P2 softmax/剪枝和 P3 interaction reweighting 的既有流程，P4 只提供短期先验修正。

### 非目标

- 不实现类别/行为族级全局校准器。
- 不新增 `/ldop/dynamic_object_predictions` 字段。
- 不新增独立诊断话题或诊断 ROS msg。
- 不把 feedback 写回 tracker，不改变当前帧 `model_state` 或 `model_covariance`。
- 不用反馈缩小 tracker 传入的当前 `model_covariance`；P4 只校准 predictor 未来 rollout 使用的 `Q_future` 尺度，并保留非零下界。
- 不引入学习式概率校准或离线训练。

### 架构边界

P4 直接收敛在 `DynamicObjectPredictor` 内部。predictor 从无状态外推器变为带短期反馈记忆的预测器：

```text
DynamicObjectTracker
  -> TrackPredictionInput[]
  -> DynamicObjectPredictor::predict()
       1. consume previous feedback cache
       2. build per-object/per-mode feedback hints
       3. generate P2 modes with feedback score bias
       4. rollout with feedback process-noise scale
       5. apply P3 interaction context
       6. store current prediction snapshot for next frame
  -> /ldop/dynamic_object_predictions
  -> /ldop/dynamic_prediction_markers
```

`Ldop` 仍只负责串接 tracker、predictor 和 UFOMap adapter；它不理解 NIS、likelihood 或 feedback state。tracker 仍只发布当前目标状态和历史快照，不接收预测反馈。

因为 predictor 需要读取并更新内部缓存，`DynamicObjectPredictor::predict()` 应改为非 `const`。当前 LDOP 只有一个处理线程调用 predictor，首版不需要给 predictor 内部 feedback cache 额外加锁；如果后续出现多线程调用，再把状态保护提升为显式互斥边界。

### 内部状态

新增 predictor 内部短期状态，不单独抽出新模块：

```text
PredictionFeedbackParams
PredictionFeedbackConfig
PredictionFeedbackBranchKey
PredictionFeedbackBranchState
PredictionFeedbackObjectState
PredictionFeedbackFrameDiagnostics
```

`PredictionFeedbackBranchKey` 用行为族和行为强度近似桶匹配 mode：

```text
behavior_type
behavior_value_bucket
```

匹配不依赖 branch index。这样 P2/P3 剪枝后分支顺序变化时，上一轮 feedback 仍能落回语义相近的 mode。

`PredictionFeedbackObjectState` 按 `object_id` 保存：

```text
last_stamp
last_prediction_snapshot
branch_states keyed by PredictionFeedbackBranchKey
missed_or_unmatched_frame_count
```

上一轮预测快照只保存 P4 必要字段：

```text
behavior_type
behavior_value
probability
time_from_start[]
position_mean[]
position_covariance_3x3[]
```

不保存完整 ROS msg 的深层对象，不复制 interaction diagnostics，也不保存 UFOMap 查询结果。P4 只需要用上一轮分支对齐当前观测。

`PredictionFeedbackBranchState` 保存平滑反馈：

```text
smoothed_log_likelihood
smoothed_nis
probability_score_bias
process_noise_scale
last_update_stamp
```

`process_noise_scale` 的默认下界是 `0.3`。它表达 predictor 对未来 rollout 过程噪声 `Q_future` 的闭环校准，不是新的 tracker 状态噪声，也不改变 tracker 传入的当前 `model_covariance`。

### 反馈计算

当当前帧输入目标 `i` 在上一轮缓存中存在同一 `object_id`，且当前目标 `matched_in_current_frame == true` 时，按当前观测时间对齐上一轮预测：

```text
dt = current_stamp - previous_prediction_stamp
sample = branch point whose time_from_start is closest to dt
```

对每条上一轮分支 `z` 计算：

```text
nu_z = observed_position - predicted_position_z
S_z = predicted_position_covariance_z + observed_position_covariance
NIS_z = nu_z^T S_z^-1 nu_z
L_z = N(nu_z; 0, S_z)
```

`observed_position` 来自当前 `TrackPredictionInput::model_state[0..2]`。`observed_position_covariance` 来自当前 `model_covariance` 的前三维位置子块。这样 P4 使用 tracker 已有不确定性，不新增一套测量噪声参数。

三维位置观测的期望 NIS 自由度为 3。首版以该自由度作为校准中心：

```text
nis_ratio = NIS_z / 3.0
```

若 `S_z` 维度不足、不可求逆或不是可用的正定位置协方差，该分支本轮反馈跳过。跳过表示“不更新反馈”，不做隐式数值合法化。

### 概率反馈

P4 不直接改最终发布分支概率，而是给下一轮 mode score 提供 bias：

```text
score_z =
  p2_score_z
+ feedback_probability_gain * probability_score_bias_z
```

`probability_score_bias_z` 来自上一轮 likelihood 的平滑值。观测更接近的分支得到更高 bias；长期解释不了观测的分支得到更低 bias。之后仍走现有 P2 softmax、`prediction_min_branch_probability` 过滤、`prediction_max_branches` 剪枝和归一化。

这样概率反馈是 mode prior 的短期调整，而不是绕过 P2/P3 的最终概率覆盖。P3 interaction reweighting 仍在 P2/P4 之后执行：

```text
P2 score + P4 feedback bias
  -> softmax / branch pruning
  -> rollout with feedback noise scale
  -> P3 interaction probability_scale
  -> final branch probabilities
```

### 过程噪声反馈

P4 只调整 predictor 未来 rollout 的过程噪声尺度，不改变当前 tracker 协方差：

```text
P_future = F * P_current * F^T + feedback_scale * Q_future
0.3 <= feedback_scale <= prediction_feedback_max_noise_scale
```

其中 `Q_future` 仍由 P2 的历史质量和 mode 不确定性得到：

```text
Q_future = Q_base * history_quality_scale * mode_uncertainty_scale
```

P4 只乘上额外尺度：

```text
Q_feedback =
  Q_base
* history_quality_scale
* mode_uncertainty_scale
* process_noise_scale
```

更新语义：

```text
if NIS_z > expected_nis:
  process_noise_scale moves upward
else:
  process_noise_scale can move downward

process_noise_scale is clamped to
  [0.3, prediction_feedback_max_noise_scale]
```

NIS 正常或偏小时允许 `process_noise_scale` 低于 1.0，因为 predictor 的 `Q_base` 是预测模块自己的未来过程噪声参数，不是 tracker 传入的当前协方差。下界默认 0.3，用来避免闭环把未来过程噪声压到 0，导致预测分支过度自信或数值退化。

### 参数策略

新增参数集中写在 `DynamicObjectPredictorParams` 中，并由 `loadParameters()` 使用三参数 `pnh_.param(name, target, default_value)` 导入。

建议参数：

```text
prediction_enable_feedback: true
prediction_feedback_max_age: 1.5
prediction_feedback_probability_gain: 1.0
prediction_feedback_noise_gain: 0.25
prediction_feedback_max_noise_scale: 3.0
prediction_feedback_smoothing_alpha: 0.35
prediction_feedback_behavior_value_bucket: 0.25
prediction_feedback_max_sample_time_error: 0.15
```

含义：

- `prediction_enable_feedback`：P4 主开关，关闭后行为应等价于当前 P3。
- `prediction_feedback_max_age`：上一轮预测过旧时不再用于残差更新。
- `prediction_feedback_probability_gain`：likelihood 对下一轮 mode score 的影响强度。
- `prediction_feedback_noise_gain`：NIS 偏大时过程噪声尺度上升速度。
- `prediction_feedback_max_noise_scale`：未来过程噪声尺度上限。
- `prediction_feedback_smoothing_alpha`：NIS 和 likelihood 的指数平滑系数。
- `prediction_feedback_behavior_value_bucket`：行为强度近似匹配粒度。
- `prediction_feedback_max_sample_time_error`：上一轮预测采样点与当前 `dt` 的最大允许时间偏差。

`process_noise_scale` 下界固定为 0.3，不暴露为 YAML 参数。该下界只作用于 predictor 未来 rollout 的 `Q_future`，不作用于 tracker 当前 `P_current`；固定非零下界可以避免反馈把过程噪声清零。

首版反馈缓存固定为上一轮预测快照，不暴露 `history_size` 参数；多帧 ADE/稳定性统计需要独立设计缓存语义后再增加参数。

### 异常处理

反馈更新遵循显式跳过策略：

- `prediction_enable_feedback == false`：不读取旧缓存，不写反馈 bias；仍可覆盖缓存以便重新启用后使用。
- `dt <= 0`：跳过本目标反馈。
- `dt > prediction_feedback_max_age`：旧状态过期并清理。
- 当前目标 `matched_in_current_frame == false`：不使用该目标更新残差，但可保留旧状态等待短时重关联。
- 找不到时间接近的上一轮预测点：跳过该分支反馈。
- 预测点没有前三维位置、协方差维度不足、位置子块不可用：跳过该分支反馈。
- 当前 tracker 输入没有前三维位置或位置协方差不可用：跳过该目标反馈。
- 某个分支无法得到反馈时，该分支下一轮使用默认 `score_bias = 0` 和 `process_noise_scale = 1.0`，表示回到 predictor 参数定义的基础未来 Q。

状态清理按当前输入 ID 集合和时间戳执行。连续消失或超过 `prediction_feedback_max_age` 的目标状态应删除，避免缓存无限增长。
