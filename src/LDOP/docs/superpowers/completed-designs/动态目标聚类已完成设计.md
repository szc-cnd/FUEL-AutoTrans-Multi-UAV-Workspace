## LDOP Dynamic Object Clustering Design

### 背景

> 实施状态（2026-05-21）：本文档记录第二阶段聚类设计时的范围和取舍；对应聚类链路已经完成，并已作为后续 tracker 的 detection 输入。第二阶段整体已完成，第三阶段短时轨迹预测也已完成，后续主线可转入 LDOP 第四阶段 planner-facing 风险地图或离线评估工具。

`LDOP` 第一阶段已经输出当前帧静态点云 `/ldop/static_cloud`、当前帧动态点云 `/ldop/dynamic_cloud` 和静态体素地图可视化。当前 `/ldop/dynamic_objects` 仍是最小占位实现：只要动态点云非空，就把整帧动态点云包成一个 `DynamicObject`。

本设计是第二阶段的第一步：只完成当前帧动态点聚类，在不改变 `/ldop/dynamic_cloud` 点云语义的前提下生成“当前帧动态目标集合”。跨帧稳定 ID、模型原生状态、状态不确定性和轨迹预测不在本次范围内。

### 目标

- 聚类只使用当前帧动态分类结果，不改变 `/ldop/static_cloud` 和 `/ldop/dynamic_cloud` 的语义。
- 保留两种可选输入路径：方案 A 消费当前帧 `/ldop/dynamic_cloud`；方案 B 消费 `UfomapMapper` 分类时同步输出的动态点和 UFOMap 聚类键。
- 沿用当前 `UfomapMapper::processInputCloud()` 顺序：先用更新前地图完成动静态分类和静态地图可视化快照，再积分当前帧；聚类工作不再改动这个顺序。
- 用聚类结果替换当前 `/ldop/dynamic_objects` 的占位单框行为。
- 每个有效 cluster 输出一个 `ldop/DynamicObject`。
- 没有有效 cluster 时输出空 `DynamicObjectArray`。

### 非目标

- 不做跨帧目标关联。
- 不维护稳定目标 ID。
- 不估计速度。
- 不输出预测字段；预测消息由后续阶段单独定义。
- 不新增 `/ldop/dynamic_clusters`、`/ldop/dynamic_object_markers` 或其他可视化话题。
- 不引入 PCL DBSCAN 或 voxblox。
- 不做 UFOMap 全图节点遍历式聚类；方案 B 只复用当前帧动态点对应的 UFOMap code/key，不把聚类职责放回 `UfomapMapper`。
- 不新增 `utils.h`。只有当无状态小函数被多个模块复用时，再考虑提取公共工具头文件。

### 方案选择与新增备选方案

当前保留两个方案用于你复核。方案 A 是已确认的最小改动方案；方案 B 是本轮新增的 UFOMap 索引复用方案。

#### 方案 A：临时 voxel hash

流程为：

```text
/ldop/dynamic_cloud
-> 读取有限 xyz 点
-> 按聚类体素尺寸落入临时 voxel hash
-> 对临时 voxel 做 6/18/26 邻域 BFS 连通
-> 将 voxel 连通块映射回原始动态点
-> 过滤点数不足或尺寸过大的 cluster
-> 用原始动态点 min/max 计算 AABB
-> 输出 DynamicObjectArray
```

优点：

- 体素连通近似 `O(N)`，邻域检查数量固定，耗时比点级半径搜索更稳定。
- 聚类尺度默认跟随 `ufomap_resolution`，参数语义和现有地图分辨率一致。
- 不需要引入新的第三方依赖。
- voxel 只负责连通关系，最终 AABB 仍由原始动态点 min/max 计算，避免体素中心导致目标框过粗。
- 对现有 `UfomapClassificationResult` 没有侵入，调试时也可以直接从 `/ldop/dynamic_cloud` 重跑聚类。

代价：

- 动态点已经在 `UfomapMapper` 中被 UFOMap 离散化过一次，clusterer 还要再做一次 point-to-voxel 映射。
- 临时 voxel hash 和 UFOMap code/key 的边界规则需要保持一致，否则极端边界点可能出现轻微差异。

#### 方案 B：复用 UFOMap 分类阶段的聚类键

流程为：

```text
UfomapMapper::classifyPoints()
-> seenFree(point) 判为动态点
-> 同步调用 runtime.map.toCodeChecked(point)
-> 保存 {原始动态点, UFOMap-derived cluster key}
-> DynamicObjectClusterer 对 cluster key 做 6/18/26 邻域 BFS
-> 将 key 连通块映射回原始动态点
-> 过滤点数不足或尺寸过大的 cluster
-> 用原始动态点 min/max 计算 AABB
-> 输出 DynamicObjectArray
```

这里的 `cluster key` 推荐是 LDOP 自己定义的轻量结构，而不是在 clusterer 公共接口里直接暴露 `ufo::Code`：

```text
UfomapVoxelCode = {raw_code, key_x, key_y, key_z, depth}
UfomapDynamicClusterPoint = {point_x, point_y, point_z, voxel_code}
```

`UfomapMapper` 内部仍然复用 UFOMap 的 `toCodeChecked()` / `ufo::Key` 语义；`raw_code` 保留 UFOMap `Code::raw()` 结果，`key_x/key_y/key_z/depth` 用于后续生成邻域。`DynamicObjectClusterer` 只理解离散 key 和邻域步长，不需要查询或修改 UFOMap。这样既复用 UFOMap 的体素索引，又避免把上层聚类模块强绑定到 UFOMap 节点 API。

当前方案 B 固定使用 UFOMap leaf key，也就是 `toCodeChecked(point)` 的默认 depth `0`。因此相邻 cell 的 key 坐标差为 `1`，`6/18/26` 邻域仍是固定数量检查，只是邻居坐标由 UFOMap key 空间生成。

优点：

- 不再从 `/ldop/dynamic_cloud` 反解析 xyz 并重新量化，少一次点云迭代和一次临时离散化。
- 聚类网格边界直接跟 UFOMap code/key 对齐，和 `seenFree(point)` 的地图尺度更一致。
- 后续如果要把分类、聚类、可视化的时间统计拆细，分类阶段已经自然带有“动态点索引输出”的位置。

代价：

- 需要扩展 `UfomapClassificationResult`，让它除了 `dynamic_cloud_msg` 之外，再携带当前帧动态点的聚类输入数据。
- `DynamicObjectClusterer` 不再是完全“只从 ROS 点云消息工作”的模块；它会优先消费 mapper 输出的结构化动态点。
- 聚类粒度跟随 UFOMap leaf resolution；方案 B 当前不单独暴露 `dynamic_cluster_voxel_size`，避免把“任意体素尺寸”误解成 UFOMap 可直接支持的控制量。

当前评估：如果我们接受 `UfomapClassificationResult` 增加一个内部聚类输入字段，方案 B 更适合 LDOP 后续演进；如果想让本次改动尽量少、聚类模块完全脱离 mapper 内部结构，则继续用方案 A。

### 架构

新增独立模块：

- `include/ldop/dynamic_object_clusterer.h`
- `src/dynamic_object_clusterer.cpp`

`DynamicObjectClusterer` 负责：

- 读取和合法化聚类参数。
- 方案 A：从 `sensor_msgs::PointCloud2` 提取有限 xyz 点，并构建临时 voxel hash。
- 方案 B：从 `UfomapClassificationResult` 的动态聚类点读取原始点和 UFOMap-derived cluster key。
- 按配置的邻域范围做 BFS 连通。
- 过滤 cluster。
- 生成 `ldop/DynamicObjectArray`。

`Ldop` 持有 `std::unique_ptr<DynamicObjectClusterer>`。方案 A 中，`processFrame()` 拿到 `ufomap_result.dynamic_cloud_msg` 后调用 clusterer；方案 B 中，`processFrame()` 优先使用 `ufomap_result.classification.dynamic_cluster_points` 生成 `dynamic_objects_msg`，`dynamic_cloud_msg` 继续只作为当前帧动态点云发布与调试输出。

`UfomapMapper` 继续负责 UFOMap 积分、`seenFree` 动静态分割、静态地图可视化和基础查询接口。方案 B 中，mapper 额外给动态点打上 UFOMap-derived cluster key，但不执行 BFS、不过滤 cluster、不生成 `DynamicObject`；聚类、检测、跟踪和预测仍不放回 mapper。

### 参数

在 `config/ldop.yaml` 增加：

```yaml
dynamic_cluster_min_points: 3
dynamic_cluster_max_extent: 3.0
dynamic_cluster_connectivity: 6  # 可选 6、18、26
```

参数语义：

- `dynamic_cluster_voxel_size`：方案 A 可以保留该参数作为临时 voxel hash 的边长；方案 B 当前不暴露该参数，固定使用 UFOMap leaf key。
- `dynamic_cluster_min_points`：cluster 中原始动态点数量小于该值时丢弃。
- `dynamic_cluster_max_extent`：cluster 原始点 AABB 对角线长度大于该值时丢弃，用于过滤大片误分割或粘连结果。
- `dynamic_cluster_connectivity`：离散 cell/key 的连通范围，只接受 `6`、`18`、`26`。非法值回退为 `6`，并在配置阶段输出 warning。

本次不增加：

- `dynamic_cluster_min_extent`
- `dynamic_cluster_max_points`
- `dynamic_cluster_merge_distance`
- `dynamic_cluster_enabled`

### 输出语义

`/ldop/dynamic_objects` 表示当前帧聚类后的动态目标集合。

每个 `DynamicObject`：

- `id`：帧内 cluster id，从 `0` 开始，每帧重新编号，不保证跨帧稳定。
- `center`：原始动态点 AABB 中心。
- `size`：原始动态点 AABB 的 x/y/z 尺寸。
- `velocity`：第一版固定为 `0`。

后续进入跟踪阶段后，`id` 将升级为跨帧稳定目标 ID，`velocity` 由跟踪状态估计填充。

### 数据流

方案 A 主流程：

```text
InputFrame
-> UfomapMapper::processInputCloud()
-> 当前帧 static_cloud / dynamic_cloud
-> DynamicObjectClusterer::buildDynamicObjectArray(dynamic_cloud)
-> publishFrame()
```

方案 B 主流程：

```text
InputFrame
-> UfomapMapper::processInputCloud()
-> 当前帧 static_cloud / dynamic_cloud + dynamic_cluster_points
-> DynamicObjectClusterer::buildDynamicObjectArray(dynamic_cluster_points)
-> publishFrame()
```

`/ldop/dynamic_cloud` 仍然是调试当前帧动态残差的主要点云输出。`/ldop/dynamic_objects` 只表达经过聚类过滤后的目标级结果。

### 错误处理

- 输入点云为空、缺少 xyz 字段或没有有限点时，输出空 `DynamicObjectArray`。
- 方案 B 中，如果动态点对应的 `toCodeChecked(point)` 失败，则该点不进入聚类输入，但仍按现有逻辑出现在 `/ldop/dynamic_cloud` 中；失败计数用 warning throttle 或调试统计暴露。
- `dynamic_cluster_min_points < 1` 时回退为 `1` 并 warning。
- `dynamic_cluster_max_extent <= 0` 或非有限时表示不启用尺寸上限过滤。
- `dynamic_cluster_connectivity` 非 `6/18/26` 时回退为 `6` 并 warning。

### 验收

- 构建通过：`catkin build ldop --no-status`。
- 不改变 `/ldop/static_cloud` 和 `/ldop/dynamic_cloud` 当前帧输出语义。
- `/ldop/dynamic_objects` 不再把整帧动态点云包成一个占位对象，而是输出聚类后的多个对象。
- 没有有效 cluster 时 `/ldop/dynamic_objects.objects` 为空。
- 如果采用方案 B，`/ldop/dynamic_objects` 的聚类输入来自 `UfomapClassificationResult` 中的结构化动态点，而不是从 `/ldop/dynamic_cloud` 反解析生成；`/ldop/dynamic_cloud` 仍完整保留当前帧动态点云输出。
