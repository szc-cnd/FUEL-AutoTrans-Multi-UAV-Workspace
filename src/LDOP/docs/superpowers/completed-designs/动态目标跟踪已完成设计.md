## LDOP Dynamic Object Tracking Design

### 背景

> 实施状态（2026-05-14）：本文档记录第二阶段 tracking 设计时的范围和取舍；对应跟踪链路已经完成，跨帧数据关联、稳定目标 ID、模型原生状态和状态不确定性维护均已由 `DynamicObjectTracker` 实现。对象类别、CV/CTRA 和类别驱动模型切换已在本文后续“动态目标分类与多运动模型 KF/EKF 设计”部分归档。

以下背景描述的是 2026-04-24 编写本设计时的代码状态。

当时 `LDOP` 第一阶段已经完成当前帧动静态点云分割与静态地图可视化；第二阶段前半段已经把动态点云聚类为当前帧动态目标集合：`DynamicObjectClusterer` 消费 `UfomapMapper` 输出的动态点和 UFOMap voxel key，在当前帧内生成 `ldop/DynamicObjectArray` 与 `/ldop/dynamic_object_markers`。

本设计当时要补齐的是第二阶段后半段能力：跨帧数据关联、稳定目标 ID、模型原生状态和状态不确定性维护。这些能力现在已经实现；速度不作为独立消息字段发布，而是按 `motion_model_type` 从 `model_state` 派生。本设计仍不包含第三阶段短时轨迹预测。

旧 `ldot_detector` 指 `/home/st/catkin/LDOT/ldot_detector`，可作为算法参考，但本次不是照搬。`LDOP` 已经有动静态判别和动态聚类，因此跟踪层只需要消费当前帧 cluster 级目标，不再引入旧流程里的动态候选判别、预测服务或双缓冲可视化框架。

LDOT 中值得保留的结构是：跟踪主流程维护轨迹列表，每条轨迹内部持有一个 Kalman filter；filter 内部再组合 motion model。`LDOP` 也采用这个边界，避免把 Kalman 公式、adaptive Q/R、协方差限制和未来多模型扩展全部塞进 `DynamicObjectTracker`。

### 目标

- 将当前帧 cluster 输出升级为跨帧稳定动态目标输出。
- 对同一动态目标尽量保持稳定 `id`。
- 第一版所有目标默认使用 3D constant-acceleration Kalman filter 估计目标中心、速度和加速度。
- 将运动模型和 Kalman filter 作为 `DynamicObjectTracker` 的内部算法组件独立出来，预留 `MotionModelType` 和 factory，后续可接入 CV/CTRA 与目标类别切换。
- 数据关联第一版只使用 3D 马氏距离，不使用 IoU、类别或外观特征。
- 包围盒尺寸只作为目标外观状态维护和输出，不参与关联代价。
- 继续复用 `ldop/DynamicObjectArray` 作为 `/ldop/dynamic_objects` 输出消息。
- `ldop/DynamicObjectArray` 的正式语义从“当前帧聚类结果”移到“tracker 输出的稳定动态目标集合”。
- 从 `ldop/DynamicObject.msg` 中移除预测数组；未来预测能力使用独立预测消息和独立预测话题输出。
- 保留聚类阶段的 `/ldop/dynamic_object_markers` 检测框可视化，并新增跟踪阶段轨迹可视化话题，形成“检测框 + 跟踪轨迹”的可视化闭环。
- 保持 `/ldop/static_cloud`、`/ldop/dynamic_cloud` 和静态地图输出语义不变。

### 非目标

- 不做短时轨迹预测。
- 不在 `/ldop/dynamic_objects` 中承载预测内容。
- 不在第一版实现预测消息或预测话题；本设计只固定预测输出应与 tracking 输出解耦。
- 不新增目标类别字段，不做人、车、无人机等分类。
- 不在第一版启用类别驱动的多模型切换；CV/CTRA 与类别映射只作为内部结构预留，不参与主流程。
- 不把跟踪职责塞回 `UfomapMapper`。
- 不把跨帧状态放进 `DynamicObjectClusterer`。
- 不使用 IoU 进行数据关联。
- 不新增独立 `TrackedObjectArray` ROS 消息。
- 不实现规划风险地图、动态障碍物膨胀或 ESDF 融合。

### 方案选择

推荐方案：新增独立 `DynamicObjectTracker`，位于 `DynamicObjectClusterer` 后面。

```text
UfomapMapper
-> DynamicObjectClusterer
-> DynamicObjectTracker
-> /ldop/dynamic_objects
```

`DynamicObjectClusterer` 继续只负责当前帧动态点连通、过滤和 AABB 估计。`DynamicObjectTracker` 负责跨帧状态：数据关联、驱动轨迹内部 filter 执行 predict/update、track id 分配、漏检保留和超时删除。这样聚类和跟踪的职责边界清楚，后续第三阶段预测也可以只消费 tracker 的稳定状态。


备选方案二：新增 `TrackedObjectArray` 消息。接口更严格，但现在 `/ldop/dynamic_objects` 在 `LDOP_design.md` 中已经是第二阶段必须输出，当前消息也已经包含 `id`、`center`、`size` 和 `velocity`，第一版没有必要扩大 ROS 接口变更。

### 架构

新增和修改模块：

- `include/ldop/utils.h`
- `include/ldop/dynamic_object_tracker.h`
- `src/dynamic_object_tracker.cpp`
- `include/ldop/multi_model_kalman_filter.h`
- `src/multi_model_kalman_filter.cpp`
- `msg/DynamicObject.msg`

`utils.h` 放置多个模块可能复用的小工具、接口函数和轻量结构体。第一版在这里增加共享 bbox 与当前帧检测结构；Kalman 状态、分类标志和预测字段不放进 `utils.h`。

`DynamicObjectTracker` 是第二阶段 tracking 的唯一主模块。它维护轨迹列表、数据关联、生命周期和输出组装。每个 `TrackState` 内部持有一个 `MultiModelKalmanFilter`；tracker 只调用 filter 的 `setDt()`、`predict()`、`update()` 和状态读取接口，不直接维护 Kalman 矩阵。

`MultiModelKalmanFilter` 是 tracker 内部算法组件，不持有 track 列表，不接触 ROS I/O。为避免第一版文件过多，`MotionModelType`、`MotionModel` 接口、`CA3D` 模型实现和 filter factory 都放在这一组文件中；后续 CV/CTRA 等模型实现膨胀后，再把 motion model 拆成单独文件。

`MultiModelKalmanFilter` 负责：

- 管理当前 filter 的 `MotionModelType`，第一版默认为 `CA3D`。
- 执行 Linear Kalman filter 的 predict/update。
- 维护 innovation buffer。
- 执行 adaptive Q/R 更新。
- 执行协方差上限钳制。
- 暴露预测/更新后的状态、协方差、位置和速度读取接口。

`MotionModel` 是 `MultiModelKalmanFilter` 文件组内的内部依赖。它负责状态维度、初始状态、初始协方差、过程噪声、测量噪声、状态转移和状态到观测的映射。第一版主流程只创建 `CA3D`，但保留 `MotionModelType` 和 factory 边界，后续可以接入 `CV3D`、`CTRA`、`HumanCA2D`、`UavCA3D` 等模型，而不重拆 tracker。

`DynamicObjectTracker` 负责：

- 读取和合法化跟踪参数。
- 消费 `DynamicObjectClusterer` 输出的当前帧 `DynamicObjectDetection` 列表。
- 基于上一帧轨迹和当前帧时间间隔驱动每条轨迹的 filter 执行预测。
- 用 3D 马氏距离构建关联代价，并根据门限接受或拒绝匹配。
- 对匹配轨迹调用 filter update。
- 对未匹配检测新建轨迹。
- 对未匹配历史轨迹执行短暂 coasting，超过阈值后删除。
- 输出跟踪后的 `ldop/DynamicObjectArray`。
- 生成跟踪轨迹 marker，用于显示稳定 track 的历史轨迹。

`Ldop` 持有 `std::unique_ptr<DynamicObjectTracker>`。`processFrame()` 先调用 `DynamicObjectClusterer::processDynamicObjects()` 获得当前帧 detection 和当前帧检测框 marker，再调用 tracker 获得稳定目标集合和轨迹 marker。发布仍通过 `publishFrame()` 完成。

`UfomapMapper` 和 `DynamicObjectClusterer` 不维护 track id，也不读取 tracker 的状态。

### 内部数据结构

第一版建议新增一个聚类和跟踪复用的轻量 bbox 结构，但不把旧 `ldot_detector::box3D` 原样搬入 LDOP。bbox 只表达目标几何框；`track_id`、速度、加速度、Kalman 协方差和漏检计数属于跟踪状态，不塞进 bbox 本身。

```text
BoundingBox3D
- center: Eigen::Vector3d
- size: Eigen::Vector3d
- yaw: double，第一版固定为 0.0，仅保留后续 OBB 扩展位置

DynamicObjectDetection
- detection_id: uint32，当前帧临时编号
- bbox: BoundingBox3D
- stamp: ros::Time

TrackHistorySample
- stamp: ros::Time
- position: Eigen::Vector3d，使用滤波后的轨迹中心
- velocity: Eigen::Vector3d，使用当前滤波状态速度
- covariance: std::array<double, 36>，公共状态 `[x,y,z,vx,vy,vz]` 的 6x6 row-major 协方差
- matched: bool，本帧是否由真实 detection update 而来；`false` 表示 coasting 样本

TrackState
- id: uint32，跨帧稳定轨迹 ID
- model_type: MotionModelType，第一版固定为 CA3D
- filter: MultiModelKalmanFilter，轨迹内部滤波器状态
- bbox: BoundingBox3D，中心和尺寸由跟踪状态维护
- history: std::deque<TrackHistorySample>，容量受 `tracking_history_size` 限制
- age: int，轨迹存在帧数
- hits: int，成功匹配次数
- missed_frames: int，连续漏检帧数
- last_stamp: ros::Time
```

`TrackHistorySample` 只保留轨迹可视化、调试和后续预测确实需要的字段。它保存与 `DynamicObject.msg` 一致的公共状态协方差，便于回看位置/速度不确定性；仍不回溯保存内部模型完整协方差、bbox 尺寸历史或完整 measurement。第一版 marker 仍只使用 `position` 绘制历史线，调试和预测可使用 `stamp/position/velocity/covariance/matched`。

`DynamicObjectClusterer` 输出当前帧 `DynamicObjectDetection` 列表，并由同一组 detection 构建 `/ldop/dynamic_object_markers`。`DynamicObjectTracker` 消费 detection 列表，输出跟踪后的 `DynamicObjectArray`。`BoundingBox3D` 可以被两个模块复用，但仍不直接暴露为 ROS 消息；`DynamicObject.msg` 是 tracking 对外接口，不再作为 clusterer 的帧内对象输出。

### 多模型 Kalman 组件

第一版主流程只使用 `MotionModelType::CA3D`。这保持当前 spec 的“单一 CA”语义，同时把 Kalman 细节从 `DynamicObjectTracker` 中拆出去。

```text
DynamicObjectTracker
-> TrackState
   -> MultiModelKalmanFilter
      -> MotionModel(CA3D，定义在同一文件组内)
```

后续目标类别接入时，只需要在 track 分类稳定后替换或重建 `MultiModelKalmanFilter` 内部的 motion model；tracker 的关联、生命周期和输出接口不需要重写。第一版不执行这个切换。

### 默认 CA3D 模型

统一使用 3D constant-acceleration 状态：

```text
x = [px, py, pz, vx, vy, vz, ax, ay, az]^T
z = [px, py, pz]^T
```

预测模型按真实时间间隔 `dt` 更新：

```text
p' = p + v * dt + 0.5 * a * dt^2
v' = v + a * dt
a' = a
```

观测只测量目标中心位置。速度和加速度由滤波器状态估计，不直接从 cluster 输入读取。


保留 LDOT 中 adaptive Q/R 和 cov limit 的语义；多模型进入主线后，这些参数统一放在 `kalman_filter/...` 分组下：

- adaptive Q：根据最近 innovation 统计调整过程噪声，降低固定 Q 对不同运动强度的敏感性。
- adaptive R：根据最近 innovation 统计调整测量噪声，缓解 cluster 中心抖动或测量质量变化。
- cov limit：固定开启，限制位置、速度和加速度协方差上限，避免长时间 coasting 或异常 `dt` 后不确定性膨胀到不可用。

实现语义上直接沿用 LDOT 当前 `multiModelKalmanFilter.h` 的思路：

- 每次 `update()` 时先把 innovation 推入固定窗口 `innovation_buffer`。
- 当窗口样本数达到 `kalman_filter/adaptive_window_size` 后，先按 `C_gamma - H * P_pred * H^T` 估计 `R`。
- 再按 `K * (C_gamma - H * (P_pred - Q_old) * H^T - R) * K^T` 估计 `Q`。
- `Q` 和 `R` 都只更新对角线，并使用 `kalman_filter/adaptive_alpha` / `kalman_filter/adaptive_r_alpha` 做 EMA 平滑。
- `kalman_filter/adaptive_min_noise_ratio` 用于给 `Q/R` 施加相对初始噪声的下限，防止估计值塌缩到过小。

这些机制不启用目标类别，也不在第一版切换 motion model；核心目标是保持参数语义与 LDOT 接近，而不是重新发明一套新公式。

### 数据关联

第一版只使用 3D 马氏距离。每条轨迹先 predict，再取预测位置和预测位置协方差：

```text
innovation = detection.center - predicted.position
cost = innovation^T * P_pos^-1 * innovation
```

`P_pos` 是预测协方差左上角 `3x3` 位置块。若 `P_pos` 奇异或数值异常，先加小正则项；仍异常时拒绝该候选匹配。

关联门限采用 3D 卡方门限：

```text
gate = chi_square_quantile(association_gate_confidence, dof = 3)
```

默认 `association_gate_confidence = 0.99`，对应门限约 `11.34`。coasting 轨迹可用 `tracking_coasting_gate_relax_factor` 放宽门限，默认 `1.0` 表示不放松，避免第一版过度吸附错误目标。

匹配求解第一版直接与 `/home/st/catkin/LDOT/ldot_detector` 对齐，使用 LDOT 当前语义下的简化 Hungarian 分配，而不是自行引入另一套完整实现：

1. 构建 `num_detections x num_tracks` 代价矩阵，行表示当前帧 detection，列表示历史 track。
2. gate 内候选填入 3D 马氏距离代价；gate 外候选填入无效大代价，例如 `1e9`。
3. 对代价矩阵执行行归约和列归约。
4. 收集归约后接近零且原始代价有效的候选项。
5. 按原始代价从小到大选择不冲突匹配，得到 `assignment[detection_index] = track_index`。
6. 对 solver 返回结果再次检查原始代价是否仍为有效代价；无效结果视为未匹配。

这样做的目的不是追求教科书版 Hungarian 的形式完整，而是保证第一版实现与 LDOT 现有行为保持一致，减少后续跨仓库比对和调参歧义。第一版先只使用 3D 马氏距离作为代价，不引入 IoU、类别或外观项；Hungarian 只负责在已有代价矩阵上求全局匹配。

### 生命周期

轨迹状态按帧维护：

- 匹配成功：执行 Kalman update，`missed_frames = 0`，`hits += 1`，`age += 1`。
- 未匹配检测：新建轨迹，分配新的单调递增 `track_id`。
- 未匹配轨迹：只执行 predict，`missed_frames += 1`，在删除前继续输出。
- 超过 `tracking_max_missed_frames`：删除轨迹。

第一版始终输出 coasting 轨迹。漏检短时间内 `/ldop/dynamic_objects` 仍保留该目标，速度来自预测状态；这有助于保持 ID 连续，也便于观察跟踪器是否正常工作。

第一版不实现 LDOT 风格的 `removeDuplicateTracks()`。主动重复轨迹清理通常要额外引入 IoU、中心距离、速度方向等启发式，还会改变 ID 生命周期；这已经超出第一版“3D 马氏距离关联 + 稳定 ID 输出”的最小闭环范围。若后续实测表明重复轨迹常见，再在独立设计里引入去重流程和对应参数。

### 尺寸维护

尺寸不参与数据关联。匹配成功时，轨迹尺寸采用指数平滑：

```text
size = alpha * detection.size + (1 - alpha) * previous_size
```

`tracking_box_size_smoothing_alpha` 默认 `0.3`。新轨迹直接使用首帧 detection 尺寸。coasting 时尺寸保持上一状态。

为了避免空尺寸或极小尺寸导致 marker 退化，输出前可对尺寸做最小下限钳制；这个下限只影响输出和可视化，不回写到关联代价。

### 参数

参数组织采用混合方案：生命周期、关联和分类参数仍保持顶层扁平；Kalman 噪声、协方差和模型参数使用 LDOT 风格的 `kalman_filter/...` 分组。旧的顶层 CA/Kalman 参数不再保留兼容入口，避免同一滤波语义被两套参数名同时控制。

除数值参数外，第一版还新增一个话题配置键：

```yaml
dynamic_track_markers_topic: /ldop/dynamic_track_markers
```

在 `config/ldop.yaml` 增加：

```yaml
tracking_history_size: 100
tracking_max_missed_frames: 5
tracking_association_gate_confidence: 0.99
tracking_coasting_gate_relax_factor: 1.0
tracking_box_size_smoothing_alpha: 0.3
tracking_default_dt: 0.1
tracking_max_dt: 0.5

kalman_filter:
  adaptive_window_size: 10
  adaptive_alpha: 0.7
  adaptive_r_alpha: 0.7
  adaptive_min_noise_ratio: 0.2
  enable_cov_limit: true
  max_pos_cov: 1.5
  max_vel_cov: 9.0
  max_acc_cov: 25.0
  ca_model:
    human:
      jerk_sigma: 1.0
      init_cov: [0.1, 0.1, 0.1, 1.0, 1.0, 10.0, 10.0]
      meas_noise: [0.1, 0.1, 0.1]
      z_process_noise: 0.01
    uav:
      jerk_sigma: 1.0
      init_cov: [0.1, 0.1, 0.1, 1.0, 1.0, 1.0, 10.0, 10.0, 10.0]
      meas_noise: [0.1, 0.1, 0.1]
  cv_model:
    acc_sigma: 3.0
    init_cov: [0.5, 0.5, 0.5, 2.0, 2.0, 2.0]
    meas_noise: [0.3, 0.3, 0.3]
  ctra_model:
    init_cov: [0.1, 0.1, 0.1, 1.0, 10.0, 0.5, 1.0]
    process_noise: [0.1, 0.1, 0.01, 1.0, 10.0, 0.1, 1.0]
    meas_noise: [0.1, 0.1, 0.1]
```

参数语义：

- `tracking_history_size`：每条轨迹保留的 `TrackHistorySample` 容量，默认 100 帧；每个样本保存 `stamp/position/velocity/covariance/matched`，其中 `covariance` 是公共状态 `[x,y,z,vx,vy,vz]` 的 6x6 row-major 协方差。该参数不影响 Kalman 状态维度，也不决定轨迹删除时机。
- `tracking_max_missed_frames`：连续漏检多少帧后删除轨迹。
- `tracking_association_gate_confidence`：3D 卡方门限置信度，合法范围建议限制在 `(0.0, 1.0)`。
- `tracking_coasting_gate_relax_factor`：漏检轨迹重新参与关联时的门限放松倍数，最小为 `1.0`；`1.0` 表示不放松，值越大越容易把漏检轨迹重新匹配到当前检测，但也更容易误关联。
- `tracking_box_size_smoothing_alpha`：bbox 尺寸指数平滑系数，合法范围 `[0.0, 1.0]`；`1.0` 表示完全使用当前帧 cluster 尺寸，`0.0` 表示保持上一帧尺寸，默认 `0.3` 表示尺寸变化偏平滑。
- `tracking_default_dt`：时间戳不可用、为零或非递增时的回退时间步长，单位为秒；手动设置为点云周期，只影响 Kalman predict 的时间间隔；触发时必须输出 throttle warning。
- `tracking_max_dt`：允许用于 predict 的最大时间间隔，单位为秒；真实帧间隔超过该值时进行钳制，避免长时间卡顿后一次预测把状态和协方差放大过头；触发时必须输出 throttle warning。
- `kalman_filter/adaptive_window_size`：adaptive Q/R 使用的 innovation 历史窗口大小；`<=1` 可关闭自适应更新。
- `kalman_filter/adaptive_alpha`：adaptive Q 平滑系数，值越大越快响应新 innovation。
- `kalman_filter/adaptive_r_alpha`：adaptive R 平滑系数，值越大越快响应测量噪声变化。
- `kalman_filter/adaptive_min_noise_ratio`：adaptive Q/R 相对初始噪声的最小比例，防止噪声被压得过小。
- `kalman_filter/max_pos_cov`、`kalman_filter/max_vel_cov`、`kalman_filter/max_acc_cov`：位置、速度、加速度协方差对角线上限。
- `kalman_filter/ca_model/human/*`：Human 的 CA2D 模型参数。
- `kalman_filter/ca_model/uav/*`：UAV 的 CA3D 模型参数。
- `kalman_filter/cv_model/*`：Other 的 CV3D 模型参数。
- `kalman_filter/ctra_model/*`：Vehicle 的 CTRA 模型参数。

第一版不增加 IoU 权重、类别权重、模型切换阈值、预测时域或预测步长参数。默认 motion model 固定为 `CA3D`，不额外暴露 `tracking_default_motion_model` 参数；`MotionModelType` 和 factory 是内部扩展点。

### 输出语义

`/ldop/dynamic_objects` 表示已跟踪动态目标集合。

每个 `DynamicObject`：

- `id`：稳定轨迹 ID，单调递增，不再是帧内 cluster id。
- `center`：Kalman update 或 predict 后的轨迹中心。
- `size`：轨迹维护的平滑 AABB 尺寸。
- `velocity`：CA 状态中的 `vx/vy/vz`。

`DynamicObject.msg` 不再包含 `prediction_time_offsets` 或 `predicted_positions`。第三阶段预测能力另建预测消息和预测话题，例如 `/ldop/dynamic_object_predictions` 与 `/ldop/dynamic_prediction_markers`，避免把当前跟踪状态和未来预测轨迹混在同一消息里。

`/ldop/dynamic_object_markers` 保留为聚类阶段检测框可视化。它展示当前帧 `DynamicObjectDetection` 的 AABB，marker id 可以是帧内 detection id，每帧先 `DELETEALL` 清理旧检测框。

为了避免 clusterer 当前实现与 spec 分叉，第一版明确沿用现有检测框 marker 约定：

- topic：`/ldop/dynamic_object_markers`
- `MarkerArray` 首元素固定为 `DELETEALL`
- namespace：`dynamic_object_bbox`
- type：`LINE_LIST`
- `scale.x = 0.05`
- color：`rgba = (0.95, 0.35, 0.10, 1.0)`
- 不显示文字标签，不单独显示 detection id

跟踪阶段新增 `/ldop/dynamic_track_markers`。当前固定输出三类 marker，不再保留“线/点/箭头三选一”的模糊描述：

- `dynamic_track_history`：`LINE_STRIP`，使用 `TrackHistorySample.position` 绘制历史轨迹线，颜色 `rgba = (0.10, 0.80, 0.95, 1.0)`，`scale.x = 0.04`
- `dynamic_track_head`：`SPHERE`，显示当前稳定轨迹头部，颜色与历史线一致，`scale.x/y/z = 0.18`
- `dynamic_track_label`：`TEXT_VIEW_FACING`，显示轨迹 ID、类别和速度模长，位置在当前目标上方

`dynamic_track_markers` 也在每帧开头先发一个 `DELETEALL`。如果轨迹当前处于 coasting 状态，则这些轨迹 marker 的 alpha 降低，用来区分“真实检测更新”和“仅预测保活”。当前仍不额外绘制速度箭头，避免 marker 数量和 RViz 负担过大。`/ldop/dynamic_object_markers` 和 `/ldop/dynamic_track_markers` 共同构成第二阶段的检测跟踪可视化：前者看当前帧检测框，后者看跨帧轨迹连续性和 track 状态。

### 数据流

```text
InputFrame
-> UfomapMapper::processInputCloud()
-> 当前帧 static_cloud / dynamic_cloud + dynamic_cluster_points
-> DynamicObjectClusterer::processDynamicObjects()
-> 当前帧 cluster detections + /ldop/dynamic_object_markers
-> DynamicObjectTracker::processDetections()
-> /ldop/dynamic_objects + /ldop/dynamic_track_markers
-> publishFrame()
```

`DynamicObjectClustererFrameResult` 携带当前帧 detection 列表和检测框 marker。`Ldop::ProcessedFrame` 中的 `dynamic_objects_msg` 保存 tracker 输出；`dynamic_object_markers_msg` 保存 clusterer 当前帧检测框；`dynamic_track_markers_msg` 保存 tracker 轨迹可视化。

### 错误处理

- 输入 detection 为空时：所有现有轨迹进入 missed/coasting 流程，超过阈值后删除；删除前继续输出 coasting 轨迹。
- 首帧没有轨迹时：所有 detection 新建轨迹。
- `header.stamp` 为零或非递增时：使用 `tracking_default_dt`，并输出 throttle warning。
- `dt > tracking_max_dt` 时：使用 `tracking_max_dt` 钳制，并输出 throttle warning，避免一次 predict 把协方差放大过头。
- 协方差矩阵非有限或不可逆时：该轨迹本帧不参与关联，保留 predict 状态并计入 missed。
- 非有限 detection 中心或尺寸：在 tracker 输入边界丢弃该 detection，clusterer 已保证的内部数据不重复检查。

### 验收

- 构建通过：`catkin build ldop --no-status`。
- `/ldop/dynamic_objects` 中同一动态目标连续帧尽量保持稳定 ID。
- `/ldop/dynamic_objects` 不再发布独立 `velocity` 字段；速度由下游按 `motion_model_type` 从 `model_state` 解释。
- `DynamicObject.msg` 不包含预测数组；预测输出未来走独立预测话题。
- `/ldop/dynamic_object_markers` 继续展示当前帧聚类检测框。
- `/ldop/dynamic_track_markers` 展示稳定 track 的历史轨迹和当前头部位置，coasting 轨迹会明显变淡。
- `/ldop/static_cloud`、`/ldop/dynamic_cloud` 和 `/ldop/static_map_markers` 输出语义不变。

本文档是 tracking 设计的增量补充；在当前合并文档中作为跟踪模块的一部分归档。当前 LDOP 主线已经有 `CA2D / CA3D / CV3D / CTRA` 运动模型和 `LinearKalmanFilter / ExtendedKalmanFilter` 底座。实现收口后，tracker 主流程已经按类别切换模型，并对外发布目标类别和当前运动模型类型。

实施状态（2026-05-14）：本文档对应的对象类别、证据积分、临时合并/分离保护和类别驱动模型切换已经完成，第二阶段整体已标记完成。后续预测能力属于第三阶段，不回写到当前跟踪消息。

### 目标

- 为已跟踪的动态目标增加对象类别分类。
- 保持 LDOP 现有 UFOMap 动静态分割职责不变；本轮不重新实现动静态分类。
- 建立类别到运动模型的映射：
  - `HUMAN` -> `CA2D` + linear KF
  - `VEHICLE` -> `CTRA` + EKF
  - `UAV` -> `CA3D` + linear KF
  - `OTHER` -> `CV3D` + linear KF
- 新轨迹对外先保持未分类状态，内部用 `CV3D` 作为初始滤波模型。
- 轨迹拥有足够历史后才分类；如果类别变化，在当前帧 Kalman update 前切换滤波模型。
- 引入 LDOT 的临时合并/分离保护机制，但只在 bbox 尺寸和点数层面适配。
- `ldop/DynamicObject.msg` 发布 `uint8 object_class`，并保留当前模型原生状态、协方差和 `motion_model_type`，供后续预测模块按模型解释。
- 分类状态、模型切换和合并/分离保护都归 `DynamicObjectTracker` 管理，不塞回 `DynamicObjectClusterer` 或 `UfomapMapper`。

### 非目标

- 不移植 LDOT 的点云运动投票式动静态分类。
- 不在本轮引入 PCA/std 类别判别。
- 不实现短时轨迹预测。
- 不向 `DynamicObject.msg` 增加 prediction 字段或 classification confidence；模型内部的 acceleration、yaw 等状态只通过 `model_state` 按 `motion_model_type` 间接表达。
- 不在本轮实现 LDOT 的 `removeDuplicateTracks()`。
- 不改变 clusterer 的连通域聚类或竖向碎片合并行为；只把已有 `point_count` 通过内部 detection 合同传给 tracker。

### LDOT 参考流程

LDOT 中和本轮相关的跟踪顺序是：

```text
runTracking()
  -> boxAssociation()
       - predict existing filters
       - build detection-track cost matrix
       - solve assignment
  -> classify matched old tracks when classification timing allows it
  -> switchKalmanModel() before the matched track update
  -> kalmanFilterAndUpdateHist()
```

LDOT 新轨迹默认是 `is_else`，并使用 3D CV filter。只有当轨迹达到 `classification_start_frame` 后才开始分类；之后按 `classification_interval_sec` 间隔重新分类，直到连续稳定分类把类别锁定。

LDOP 保留“先关联、后分类、再在 Kalman update 前切模型”的时序，但不照搬 LDOT 的固定间隔和连续次数锁定。LDOT 里混在一起的两个概念在 LDOP 中拆开：

- 新轨迹内部默认滤波模型：`CV3D`
- 新轨迹对外类别：`UNKNOWN`

这样新目标刚出现时不会被下游误认为已经确认是 `OTHER`。类别稳定性改用轨迹内部的证据积分来判断，短时误判和短时遮挡不会直接打断历史判断。

### 数据合同

#### DynamicObject.msg

当前对外 ROS 消息包含类别枚举、运动模型枚举、目标尺寸、模型原生状态和模型原生协方差。类别相关字段为：

```text
uint8 CLASS_UNKNOWN=0
uint8 CLASS_HUMAN=1
uint8 CLASS_VEHICLE=2
uint8 CLASS_UAV=3
uint8 CLASS_OTHER=4

uint8 object_class
```

语义如下：

- `CLASS_UNKNOWN`：轨迹还没有达到可靠分类条件。
- `CLASS_OTHER`：已经执行过分类，但不满足 human、vehicle 或 UAV 规则。

当前接口不再单独发布公共 `center/velocity/covariance` 字段。目标中心固定在 `model_state[0..2]`；速度和协方差由下游结合 `motion_model_type` 解释 `model_state/model_covariance` 得到。

#### 内部 Detection

给 `DynamicObjectDetection` 增加点数：

```text
point_count: std::size_t
```

`DynamicObjectClusterer` 现在已经在 `Fragment::point_count` 中统计点数；`fragmentToDetection()` 只需要把它复制到 detection。这个字段只属于 clusterer 到 tracker 的内部合同，不改变 ROS 消息。

`point_count` 只用于临时合并/分离保护。tracker 不消费原始点云，也不维护点云历史。

#### 内部分类状态

新增一个轻量内部枚举：

```text
ObjectClass
- Unknown
- Human
- Vehicle
- Uav
- Other
```

每个 `TrackState` 增加这些状态：

- `object_class`：当前对外类别，初始为 `Unknown`
- `classification_scores`：`Human / Vehicle / Uav / Other` 四类证据分数，不给 `Unknown` 积分
- `max_history_size`：该轨迹已经接受的历史最大 bbox 尺寸
- `last_point_count`：上一帧匹配 detection 的点数
- `large_size_counter`：连续临时合并计数
- `small_size_counter`：连续临时分离计数

这些状态属于 `TrackState`，因为它们依赖轨迹历史和匹配结果，不是当前帧 detection 的局部属性。

### 单帧流程

`DynamicObjectTracker::processDynamicTracks()` 的单帧流程调整为：

```text
processDynamicTracks(header, detections)
  -> predictTracks(header.stamp)
  -> buildCostMatrix()
  -> selectAssociations()
  -> for each match:
       prepareMatchedTrackForUpdate(track, detection, stamp)
         -> update merge/separation protection
         -> classify current observation when hits are sufficient
         -> update classification evidence if observation is reliable
         -> switch model if confirmed class changed
       updateMatchedTrack(track, detection, stamp)
  -> createTrack() for unsuppressed unmatched detections
  -> coastTrack() for unmatched old tracks
  -> deleteExpiredTracks()
  -> buildOutput()
  -> buildTrackMarkers()
```

关键顺序是：先完成关联，再对匹配到的旧轨迹做分类和模型切换，最后才执行当前帧 Kalman update。

### 新轨迹语义

创建新轨迹时：

- `object_class = Unknown`
- `model_type = CV3D`
- filter 使用 `MotionModelType::CV3D`
- `max_history_size = detection.bbox.size`
- `last_point_count = detection.point_count`
- 分类证据分数和尺寸突变计数器清零
- 对外输出在真正分类前保持 `CLASS_UNKNOWN`

这样既贴近 LDOT 的稳定默认模型，又不会把未分类目标对外说成已确认 `OTHER`。

### 类别证据更新

分类只对匹配成功的旧轨迹执行。

使用这些参数：

- `classification_start_frame`
- `classification_score_decay`
- `classification_score_increment`
- `classification_confirm_score`
- `classification_switch_margin`

满足以下条件时才允许更新类别证据：

- `track.hits >= classification_start_frame`
- 当前帧成功匹配 detection
- 当前 detection 没有处在临时合并、临时分离或疑似遮挡观测状态

满足条件后，每个匹配帧都执行一次轻量 bbox 分类，不再等待固定时间间隔。这样稳定目标可以更快积累证据，偶发误判也不会像连续次数方案那样直接清零。

证据更新规则：

- 每次可靠观测先让四个类别分数乘以 `classification_score_decay`。
- 当前帧分类结果对应的类别增加 `classification_score_increment`。
- 取最高分和第二高分；如果最高分大于等于 `classification_confirm_score`，且领先第二名至少 `classification_switch_margin`，则把最高分类别作为确认类别。
- 如果确认类别和 `object_class` 不同，就在本帧 Kalman update 前切换运动模型。

`Unknown` 不参与积分。轨迹在任意类别达到确认条件前，对外继续发布 `CLASS_UNKNOWN`。

这个策略不再需要 `classification_locked`。类别不是永久锁死，而是通过分数和 margin 形成滞回：已经确认的类别会保留，只有另一个类别积累出明显更强的证据时才切换。`Other` 可以被确认并发布，但它也不会变成永久锁定状态；后续如果 human、vehicle 或 UAV 证据足够强，仍然可以切走。

#### 短时遮挡

短时遮挡或短时未匹配时，轨迹进入已有 coasting 流程。coasting 帧不更新 `classification_scores`，也不降低已有分数；缺少观测只代表没有新证据，不代表类别判断被推翻。

遮挡后重新匹配到目标，如果 bbox 尺寸明显变小或点数突降，先按临时分离处理。这些疑似遮挡残片帧冻结类别证据，等尺寸和点数恢复稳定后再继续积分。

模型切换只允许发生在有可靠匹配 detection 的帧内；coasting 阶段保持原类别和原运动模型。

### 临时合并/分离保护

分类前先按 LDOT 逻辑更新尺寸稳定状态。LDOP 的输入来自 detection，不引入原始点云历史。

输入：

- 当前 detection 的 bbox 尺寸
- 当前 detection 的点数
- 轨迹的 `max_history_size`
- 轨迹的 `last_point_count`

参数：

- `classification_size_change_ratio`
- `classification_point_count_change_ratio`
- `classification_size_change_confirm_frames`

派生阈值：

```text
merge threshold = 1.0 + ratio
separation threshold = 1.0 - ratio
```

计算量：

- `size_ratio_x/y/z = current_size / max(max_history_size, epsilon)`
- `max_size_ratio = max(size_ratio_x, size_ratio_y, size_ratio_z)`
- `point_ratio = current_point_count / max(last_point_count, 1)`

规则：

- 如果 `max_size_ratio > 1 + classification_size_change_ratio`，或 `point_ratio > 1 + classification_point_count_change_ratio`，视为临时合并。
- 如果 `max_size_ratio < 1 - classification_size_change_ratio`，或 `point_ratio < 1 - classification_point_count_change_ratio`，视为临时分离。
- 临时合并时递增 `large_size_counter`，并重置 `small_size_counter`。
- 临时分离时递增 `small_size_counter`，并重置 `large_size_counter`。
- 如果 `large_size_counter >= classification_size_change_confirm_frames`，接受更大的目标尺寸，并允许 `max_history_size` 继续增长。
- 如果 `small_size_counter > classification_size_change_confirm_frames`，接受更小的目标尺寸，并把 `max_history_size` 重置为当前尺寸。
- 在合并/分离仍是临时状态时，用 `max_history_size` 代替当前尺寸参与分类和 bbox 尺寸稳定。
- 在合并/分离仍是临时状态时，冻结类别证据分数，不让粘连或残片帧影响类别判断。
- 如果没有临时合并/分离，则按分量用当前尺寸更新 `max_history_size`。

这个机制只保护分类和 bbox 尺寸稳定，防止瞬时粘连或分裂污染类别判断。它不删除轨迹、不合并轨迹，也不改变 clusterer 输出。

### 分类规则

分类使用 LDOT 的核心 bbox/质心规则，并按 LDOP 当前能提供的数据做适配。

输入：

- 经过临时合并/分离保护后的稳定尺寸
- 当前 detection 中心高度

参数：

- `classify_human_threshold: [z_width_ratio, centroid_z_ratio]`
- `classify_vehicle_threshold: [xy_width_ratio, centroid_z_ratio]`
- `classify_uav_threshold: [max_size, centroid_z_ratio]`

分类规则：

- `Human`：`z_width >= max(x_width, y_width) * human_z_width_ratio`，且 `centroid_z < z_width * human_centroid_z_ratio`
- `Vehicle`：`max(x_width, y_width) >= z_width * vehicle_xy_width_ratio`，且 `centroid_z < z_width * vehicle_centroid_z_ratio`
- `UAV`：三个尺寸都小于 `uav_max_size`，且 `centroid_z > z_width * uav_centroid_z_ratio`
- 其他情况为 `Other`

分类结果只是当前帧观测，不直接等同于轨迹类别。轨迹类别由上一节的证据积分确认。

LDOT 的 `fix_size` 同时承担“分类锁定”和“尺寸固定”两层含义，LDOP 本轮不照搬这种耦合。类别稳定由 `classification_scores`、`classification_confirm_score` 和 `classification_switch_margin` 判断；bbox 输出尺寸仍按 tracker 的尺寸平滑和临时合并/分离保护更新。换句话说，`classification_size_change_confirm_frames` 只判断尺寸/点数突变是否真实，类别证据积分只判断类别是否足够可靠。

### 模型映射与切换

模型映射：

```text
Unknown -> 保持当前模型
Human   -> CA2D
Vehicle -> CTRA
UAV     -> CA3D
Other   -> CV3D
```

如果一次分类导致目标模型变化，必须在当前帧 matched-track update 前切换 filter。

状态迁移要尽量保留位置和世界坐标系速度：

- 从 `CV3D` 读出 `[x, y, z, vx, vy, vz]`
- 从 `CA2D` 读出 `[x, y, z, vx, vy, ax, ay]`，并令 `vz = 0`
- 从 `CA3D` 读出 `[x, y, z, vx, vy, vz, ax, ay, az]`
- 从 `CTRA` 读出 `[x, y, z, v, a, yaw, yaw_rate]`，并转换为 `vx = v*cos(yaw)`、`vy = v*sin(yaw)`、`vz = 0`

新模型初始化状态：

- `Human/CA2D`：`[x, y, z, vx, vy, 0, 0]`
- `Vehicle/CTRA`：`[x, y, z, speed, 0, yaw, 0]`
- `UAV/CA3D`：`[x, y, z, vx, vy, vz, 0, 0, 0]`
- `Other/CV3D`：`[x, y, z, vx, vy, vz]`

车辆 yaw 的处理：

- 如果水平速度足够大，用 `atan2(vy, vx)`。
- 如果速度接近 0，且旧模型已经是 CTRA，则保留旧 yaw。
- 否则使用 `0`。

切换后，用迁移后的状态初始化新 filter，并保留 track id、bbox、history、hits 和分类状态。

### 参数组织

采用混合参数组织：

- 已有生命周期和关联参数继续使用扁平 `tracking_*`。
- 对象类别分类参数使用扁平 `classification_*` 和 `classify_*`。
- 多运动模型 Kalman 参数使用 LDOT 风格的 `kalman_filter/...` 分组。

分类参数：

```yaml
classification_start_frame: 10
classification_score_decay: 0.85
classification_score_increment: 1.0
classification_confirm_score: 3.0
classification_switch_margin: 1.5
classification_size_change_ratio: 0.5
classification_point_count_change_ratio: 0.5
classification_size_change_confirm_frames: 5
classify_human_threshold: [1.1, 0.8]
classify_vehicle_threshold: [1.5, 0.7]
classify_uav_threshold: [0.6, 1.5]
```

### 输出与可视化

`buildOutput()` 对外发布：

- 稳定 `id`
- 平滑后的 `size`
- 当前模型原生 `model_state`
- 当前模型原生 `model_covariance`
- `object_class`
- `motion_model_type`

`DynamicObject.msg` 不发布预测数组；第三阶段预测仍走独立话题。

RViz 话题保持检测和跟踪分离：

- `/ldop/dynamic_object_markers`：clusterer 当前帧 detection box
- `/ldop/dynamic_track_markers`：tracker 历史线、轨迹头部球，以及目标上方 ID/类别/速度文字

可以选择按类别给轨迹 marker 上色，但这只能是 `DynamicObjectTracker` 内部可视化行为，不应要求新增对外消息。若实现类别上色，coasting 状态的 alpha 降低仍然优先生效。

### 实现注意事项

- 本轮删除 `classification_interval_sec`、`classification_stable_confirmations` 和 `classify_xy_distance_threshold`。平台近场保护需要清晰的平台位姿输入和实际误分类证据，后续如果要做，再作为独立保护机制加入。
- 分类状态保留在 `TrackState` 内部。除非后续出现明显重复逻辑或稳定复用边界，否则不要为了“看起来更模块化”抽一个独立 classifier 类。
