# 动态目标轨迹预测接入 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 将现有 `DynamicObjectPredictor` 接入 LDOP 实时主处理链，发布动态目标未来短时轨迹和 RViz 可视化结果。

**Architecture:** `DynamicObjectTracker` 每帧输出稳定目标的 `TrackPredictionInput`，`Ldop::processFrame()` 将这些输入同步交给现有 `DynamicObjectPredictor`。预测器同时生成 `DynamicObjectPredictionArray` 和 `MarkerArray`，由 `Ldop::publishFrame()` 发布；UFOMap 通过已经存在的 `UfomapPredictionMapQuery` 为交互感知预测提供静态地图查询。

**Tech Stack:** ROS Noetic、roscpp、C++20、Eigen、UFOMap、catkin、RViz MarkerArray。

## Global Constraints

- 预测时长保持 `prediction_horizon: 1.0` 秒。
- 每个目标最多保留 `prediction_max_branches: 3` 个预测分支。
- 预测输入使用 tracker 的稳定 ID、模型状态、协方差和历史轨迹，不直接读取第二份点云。
- 不修改动态聚类、地面滤波、目标跟踪、目标分类和 ID 关联逻辑。
- 预测失败时仍发布当前帧的空预测结果和清理 marker，不能阻断动态检测主链路。
- 远程端只同步本次涉及的文件，不删除或覆盖其他远程未提交修改。
- 按用户当前流程使用 `/home/oem/scripts/ros_start_ldop_detection.sh` 启动、`/home/oem/scripts/ros_stop_all.sh` 关闭。
- 不执行完整自动化测试套件；使用远程编译和现场 ROS 话题/RViz 观察验证。
- Git 提交备注使用中文。

### Task 1: 接入主处理链中的预测调用

**Files:**
- Modify: `src/ldop.cpp:346-389`
- Read: `include/ldop/ldop.h:58-70`
- Read: `include/ldop/dynamic_object_tracker.h:95-105`
- Read: `include/ldop/dynamic_object_predictor.h:115-126`

**Interfaces:**
- Consumes: `tracker_result.prediction_inputs`, type `std::vector<TrackPredictionInput>`。
- Consumes: `processed.dynamic_cloud_msg.header`, type `std_msgs::Header`。
- Consumes: existing `UfomapPredictionMapQuery prediction_map_query` implementing `PredictionMapQuery`。
- Produces: `processed.dynamic_predictions_msg`, type `ldop::DynamicObjectPredictionArray`。
- Produces: `processed.dynamic_prediction_markers_msg`, type `visualization_msgs::MarkerArray`。
- Produces: `processed.timing.processing_summary.prediction_module_ms`, type `double`。

- [ ] **Step 1: 确认 tracker 输入在移动消息前仍可用**

在 `processFrame()` 中保留当前顺序：先从 `dynamic_object_tracker_->processDynamicTracks()` 得到 `tracker_result`，只移动其中的 `dynamic_objects_msg` 和 `dynamic_track_markers_msg`，不要移动 `prediction_inputs`。预测调用必须使用与 tracker 相同的 `processed.dynamic_cloud_msg.header`。

- [ ] **Step 2: 写入预测器调用**

在 tracker 输出之后、姿态融合之前或之后的同一处理线程中加入同步调用。调用结构固定为：

```cpp
const UfomapPredictionMapQuery prediction_map_query(*ufomap_mapper_);
const DynamicObjectPredictorFrameResult prediction_result =
    dynamic_object_predictor_->predict(processed.dynamic_cloud_msg.header,
                                        tracker_result.prediction_inputs,
                                        &prediction_map_query);
processed.dynamic_predictions_msg = prediction_result.predictions_msg;
processed.dynamic_prediction_markers_msg = prediction_result.prediction_markers_msg;
processed.timing.processing_summary.prediction_module_ms =
    prediction_result.timing.predict_total_ms;
```

`prediction_map_query` 只在本次同步调用期间存活，不能把其地址保存到 predictor 或异步线程中。空的 `prediction_inputs` 也正常调用 predictor，让它生成带 `DELETEALL` 的空 marker，清除上一帧轨迹。

- [ ] **Step 3: 添加预测异常隔离**

在 `src/ldop.cpp` 的 include 区域加入 `<exception>`，再用 `try/catch (const std::exception& ex)` 包住预测器调用。异常时按当前 header 初始化空的 `DynamicObjectPredictionArray`，并构造一个 `visualization_msgs::Marker`：`action = visualization_msgs::Marker::DELETEALL`、`ns = "dynamic_predictions"`。记录节流警告和本次预测耗时，将耗时写入 `prediction_module_ms`，然后继续执行姿态融合和当前帧发布。

- [ ] **Step 4: 做静态检查**

确认 `ProcessedFrame` 已包含两个预测字段，预测结果没有写入 `dynamic_objects_msg` 或其他检测输出，且 `prediction_module_ms` 不再固定为 `0.0`。运行：

```powershell

Select-String -Path src\ldop.cpp -Pattern 'dynamic_object_predictor_->predict|prediction_module_ms'
```

预期：只出现新的预测调用、异常处理和耗时赋值，不改变 tracker 的调用参数。
