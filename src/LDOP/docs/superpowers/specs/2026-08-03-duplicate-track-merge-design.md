# 动态障碍物近邻重复轨迹合并设计

日期：2026-08-03

## 背景

现场实时话题观察到，同一个约 30 cm 小球附近会同时出现两条轨迹。例如一条轨迹的中心约为 `(1.7, -0.1, 0.51)`，另一条约为 `(1.8, 0.1～0.3, 0.5～0.6)`。两条轨迹会交替出现在 `/ldop/dynamic_objects`，因此下游看起来像目标 ID 发生跳变。

此前增加的漏检保活已经能让同一轨迹在短暂空帧后恢复原 ID，但不能处理当前帧点云被分成两个近邻点簇、从而形成两条已存在轨迹的情况。

## 目标与非目标

- 目标：在同一目标被分裂成多个近邻动态点簇时，只对外保留一条稳定轨迹，并优先保留较早且命中更充分的 ID。
- 目标：保留现有短时漏检保活机制，避免目标暂时遮挡后重新建 ID。
- 非目标：不放宽动态点簇的最小点数，不改变地面滤波、天花板滤波和 UFOMap 静态地图逻辑。

## 方案

在 `DynamicObjectTracker::processDynamicTracks()` 完成当前帧关联、创建新轨迹和漏检轨迹 coast 后，删除过期轨迹前，执行一次近邻重复轨迹合并：

1. 新增 ROS 参数 `tracking_duplicate_merge_distance`，默认值为 `0.45 m`。该值覆盖现场测得的同一小球两个点簇中心约 `0.2～0.4 m` 的间隔。
2. 对当前内部轨迹两两比较三维预测中心；中心距离不超过该阈值时，视为重复轨迹候选。
3. 候选轨迹中优先保留：已经达到对外发布命中数的轨迹、命中次数更多的轨迹、漏检帧更少的轨迹、年龄更长的轨迹；仍相同则保留较小的旧 ID。
4. 删除被合并的较弱轨迹，保留轨迹的 Kalman 状态、历史、尺寸平滑状态和 ID 不变。合并完成后再执行过期删除、对外输出和预测输入构建。
5. 合并距离设为零或负数时关闭该功能，便于后续对比调试。

## 风险控制

该合并规则只作用于三维中心非常接近的轨迹，不会扩大数据关联门限，也不会把远距离误检直接关联到小球。比赛当前是单个动态小球检测场景，近邻合并可以同时抑制小球碎片轨迹和旁边固定杆造成的重复框；若未来需要同时跟踪相距小于 0.45 m 的多个真实目标，应再降低阈值或增加目标类别/点簇形状约束。

## 验证方式

遵循当前现场调试约定，不运行自动测试。远程重新编译并启动后：

- 让小球连续运动并经历点数变少或短暂遮挡；
- 观察 `/ldop/dynamic_objects` 是否只保留一个近邻目标 ID；
- 确认小球重新出现时沿用原 ID，且不再在小球附近同时出现第二个重复 ID；
- 确认目标离开后不会因内部轨迹保活长期残留。
