# 动态目标轨迹预测接入设计

## 目标

将已经实现但尚未接入主处理链的 `DynamicObjectPredictor` 接入 LDOP 实时处理流程，为动态避障提供未来短时轨迹预测，同时保留现有动态点云、目标框、目标 ID 和速度输出不变。

## 范围

- 每个处理帧使用 `DynamicObjectTracker` 输出的稳定目标及其历史信息构造预测输入。
- 调用现有 `DynamicObjectPredictor::predict()`，使用当前参数生成未来 1 秒、最多 3 个行为分支。
- 发布预测消息 `/ldop/dynamic_object_predictions`。
- 发布预测可视化 `/ldop/dynamic_prediction_markers`。
- 在 LDOP RViz 配置中启用预测轨迹显示，并使用独立颜色和线宽，避免与动态点云及目标框混淆。
- 将预测模块耗时写入已有处理统计。

不在本次范围内修改聚类、地面滤波、动态目标跟踪、目标分类和 ID 关联逻辑。

## 数据流

```text
UFOMap 动态点
    -> DynamicObjectClusterer
    -> DynamicObjectTracker
       (稳定 ID、状态、速度、历史轨迹)
    -> buildPredictionInputs()
    -> DynamicObjectPredictor::predict()
       (未来 1 秒，多分支)
    -> DynamicObjectPredictionArray
    -> /ldop/dynamic_object_predictions

    -> DynamicPredictionMarkers
    -> /ldop/dynamic_prediction_markers
    -> RViz 预测轨迹显示
```

预测模块按当前 tracker 的输出顺序运行，预测输入与当前帧使用同一个 header，保证时间戳和坐标系一致。无动态目标时发布空预测消息和空 marker 数组，避免下游继续使用上一帧的陈旧轨迹。

## 代码改动

### `src/ldop.cpp`

- 在 `processFrame()` 中取得 tracker 的预测输入并调用 `dynamic_object_predictor_->predict()`。
- 将预测消息、预测 marker 和预测耗时写入 `ProcessedFrame`。
- 在 `publishFrame()` 中发布两个预测话题。
- 对预测器异常或空输入保持节点主检测链路可用，并发布当前帧的空预测结果。

### `include/ldop/ldop.h`

现有 `ProcessedFrame`、预测 publisher 和 predictor 成员继续使用；只补充必要的处理阶段接口或注释，不引入第二套消息结构。

### `launch/rviz/ldop_rviz.rviz`

启用现有 `DynamicPrediction` display，检查其话题指向 `/ldop/dynamic_prediction_markers`，并调整为清晰可见的预测线显示。

### 配置

保留当前预测参数：

- `prediction_horizon: 1.0`
- `prediction_max_branches: 3`
- `prediction_min_branch_probability: 0.05`
- `prediction_history_window: 20`

本次不额外放大预测范围，避免预测线遮挡实时检测结果。

## 运行与验证

按照用户当前流程使用 `/home/oem/scripts/ros_start_ldop_detection.sh` 启动，使用 `/home/oem/scripts/ros_stop_all.sh` 关闭。验证重点为：

1. 节点启动后两个预测话题存在且持续发布。
2. 小球移动时预测消息中的 `track_id` 与 `/ldop/dynamic_objects` 一致。
3. 预测点时间从 0 逐步增加到约 1 秒，位置沿当前速度方向变化。
4. 小球停止或消失后预测分支不会无限保留。
5. 原有动态点云、框、ID 和检测接口继续正常发布。

验证采用编译检查和现场 ROS 话题/RViz 观察，不执行完整自动化测试套件，符合当前调试流程。
